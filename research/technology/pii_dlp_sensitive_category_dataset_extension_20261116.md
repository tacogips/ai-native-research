# 要配慮個人情報・本人確認書類・認証情報・音声映像の検知用データセット拡張設計

設計日：2026年11月16日。DLPは機密情報の検知・保護を指す。要配慮個人情報は個人情報保護法が定める、不当な差別や偏見が生じないよう特に配慮を要する個人情報を指す。個人識別符号は、同法が定める、それだけで本人を識別できる番号や身体的特徴の符号を指す。

対象は[LIGHT生成器](../../scripts/pii_image_dataset/README.md)と[Workspace DLP比較試験](../../scripts/workspace_dlp_benchmark/README.md)。本文書は設計案であり、生成器の変更・生成・製品での測定は行っていない。法令上の分類は公開の法令・指針に基づく試験用の注釈であり、個別事案の法的判断ではない。

**結論：** 指定された19項目のうち、現行のLIGHTに正解の種類があるのは14項目。ただし要配慮個人情報は各種類2〜6元文書で、値はほぼ1種類の固定文であり、検知率を判定できる量と多様性がない。保険情報・在留カード・保険証・資産・パスワード・顔・音声・映像は正解の種類自体がない。文字で表せる項目と、合成音声・合成画像による「存在」の検知は設計できる。実在者の顔・声による本人識別、生体特徴量の符号、実物と同等の証明書画像、法解釈が分かれる境界例の確定は難しい。

### 現行の構造上の問題

- **見出しが答えになっている：** 陽性は「病歴：糖尿病の診断を受けた」のように、正解の種類名と同じ見出しを持つ。語句一覧の検知器が見出しだけで一致し、本文の意味を検知したかを測れない。
- **値が固定：** 要配慮個人情報は、各種類が一つの文の反復である。一つの語句に一致するかどうかで全件の結果が決まる。
- **紛らわしい陰性が少ない：** 「システム障害」「国籍だけの記載」のように、同じ語を含むが対象外の例がない。
- **正解のない秘密値が入力にある：** `embedded.py`はXLSXの変更用パスワードから作った一方向変換値を`drive_upload`内の資料へ書き込むが、正解の種類として登録していない。認証情報を検知する製品がこれを検知すると偽陽性として数えられる。

## 2. 法令上の区分

要配慮個人情報は、法律の6区分と政令の5区分で閉じた一覧である。[L1,L2,L3]

| 区分 | 現行 | 拡張で追加する内容 |
|---|---|---|
| 人種 | あり | 民族・出自の申告。国籍だけの記載は人種に当たらないため境界の陰性にする [L3] |
| 信条 | あり | 宗教に加え、思想・政治的信条 |
| 社会的身分 | あり | 指針の例に沿う表現。単なる職業上の地位・学歴は含まないことを陰性に使う [L3] |
| 病歴 | あり | 慢性疾患、がん、感染症、精神疾患、難病を表現違いで追加 |
| 犯罪の経歴 | あり | 前科、執行猶予等の表現違い |
| 犯罪により害を被った事実 | あり | 被害届、被害相談等 |
| 心身の機能の障害（政令） | 聴覚のみ | 身体・知的・精神（発達障害を含む）、障害者手帳の等級 |
| 健康診断等の結果（政令） | 1文 | 検査値の表、判定区分、遺伝子検査の結果の説明文 |
| 医師等による指導・診療・調剤（政令） | 1文 | 保健指導、処方、受診記録 |
| 刑事事件の手続（政令） | 1文 | 逮捕、起訴、勾留等 |
| 少年の保護事件の手続（政令） | 1文 | 審判、保護処分等 |

本人を推知させるだけの情報（宗教書の購入記録、特定の診療科の近くにいた位置情報等）は要配慮個人情報に含まれないとされる。[L3] この境界は、形式検知と法的分類を分けて正解を付ける対象にする。

個人識別符号は、旅券番号、運転免許証番号、個人番号、住民票コード、基礎年金番号、各種保険の被保険者証の符号等の番号と、顔・指紋・声紋等の身体的特徴を本人認証用に変換した符号である。[L1,L2,L4] 在留カード番号を規則が定める符号に含むかは、今回の検索結果だけでは条文を確認できなかった。生成前に現行の施行規則を確認する。

## 3. 設計できる項目

### 3.1 共通の設計

現行の生成器を拡張し、項目ごとに値の候補群と文脈の型を持たせる。正解には次の注釈を追加する。

| 注釈 | 値 | 用途 |
|---|---|---|
| `legal_class` | 要配慮の11区分、個人識別符号、特定個人情報（個人番号を含む情報）、個人情報、法定外の機微情報、非個人 | 法的区分と製品の検知種別を分けて採点 |
| `subject` | 本人、家族、第三者、なし | 家族の病歴や一般解説を本人の事実と分ける |
| `assertion` | 肯定、否定、過去、仮定 | 「糖尿病ではない」等を一律陰性にしない |
| `certainty` | 明確、判断保留 | 法解釈が分かれる例を主指標から除外し別集計 |
| `cue` | 見出しあり、見出しなし、表の列名、自由文 | 見出し語への依存を測る |

各項目は、見出しありと見出しなしの対、肯定と否定の対、本人と一般解説の対を必ず作る。LIGHTの目安は、各項目で陽性6元文書（値3種×文脈2種）と陰性6元文書とする。現行の各2元文書から増やすが、文字資料なので容量への影響は小さい。

Workspace DLPでの扱いは項目で異なる。既存の[117項目比較](sensitive_information_detection_item_matrix_20261112.md)では、病名・人種は標準検知、障害・宗教・在留カード・健康保険の番号は独自規則（正規表現・語句一覧）で構成する案、顔は標準対応を確認できず、音声・動画は対象外である。独自規則で測る項目は、Googleの検知器ではなく自作規則の品質を測ることになるため、観測記録に`detector_origin`（標準／独自）を残す。

### 3.2 要配慮個人情報

| 項目 | 陽性の設計 | 陰性・境界の設計 |
|---|---|---|
| 病歴・診療 | 疾患5系統×表現（診断名、既往歴欄、通院中、休職理由、処方薬名） | 疾患の一般解説、保険商品名に含む疾患名、「既往歴なし」は判断保留 |
| 健康診断 | 検査値の表（血圧、血糖、肝機能）、判定区分、再検査通知、特定保健指導。CSV・表・帳票PDF | 基準値の一般表、空欄の問診票、機器の検査結果。「異常なし」は判断保留 |
| 障害 | 身体・知的・精神・発達、手帳の等級、合理的配慮の申出 | 「システム障害」「通信障害」、バリアフリー設備の案内、制度の一般説明 |
| 犯罪歴・手続・被害 | 前科、逮捕・起訴、少年審判、被害届を本人に帰属 | 法令解説、架空企業への不正アクセスの事案説明（個人の帰属なし）、「犯罪歴なし」は判断保留 |
| 人種・信条・社会的身分 | 民族の申告、信仰・支持政党の申告、指針の例に沿う出自の記載 | 国籍だけの記載、宗教施設の観光案内、政党の政策一般、宗教書の購入記録（推知のみ） |

### 3.3 保険情報

「保険情報」は意味が広いため、三つに分ける。

| 区分 | 陽性 | 陰性 | 法的区分 |
|---|---|---|---|
| 公的医療保険の資格 | 保険者番号、記号・番号・枝番、資格確認書の記載 | 保険料率表、空欄の届出様式 | 被保険者証の符号は個人識別符号 [L4] |
| 雇用保険・年金 | 雇用保険被保険者番号、基礎年金番号 | 制度の一般説明 | 基礎年金番号は個人識別符号。雇用保険は現行規則で確認 |
| 民間保険 | 証券番号、契約者・被保険者・受取人、保険金額、告知事項、給付金請求の診断名 | 商品案内、保険料の試算表（個人なし） | 告知事項・診断名は要配慮（病歴）と重なる |

番号の桁数・検査数字は、公開された様式・仕様を確認してから生成する。確認できない場合は桁数だけ合わせ、`checksum_valid=null`とする。

### 3.4 本人確認書類と番号

| 項目 | 設計 |
|---|---|
| 在留カード | 番号は英数字12桁（公開の届出様式に記載欄の説明がある）[L5]。在留資格・在留期限を併記した例と番号だけの例。陰性は12桁英数字の製品シリアル、在留資格制度の説明 |
| 保険証・資格確認書 | 番号と独自様式の見本画像。陰性は空欄の様式 |
| 免許証・旅券 | 現行を維持し、検査数字の正誤の対を追加 |
| 見本画像の方針 | 現行の免許証見本と同じく、「架空見本」の表示、独自の配置、実物の配色・紋様・偽造防止要素を再現しない。顔領域は3.7の合成顔か図形 |

### 3.5 金融・経歴・勤務先

| 項目 | 陽性 | 陰性 |
|---|---|---|
| 資産 | 預金残高、保有銘柄と数量、不動産の所在と評価額、ローン残高、暗号資産の公開アドレスを本人に帰属 | 法人の貸借対照表、投資信託の商品説明、物件広告 |
| 職歴・学歴 | 履歴書の表、自由文の経歴、卒業証明書の見本。値は10種以上 | 求人票の応募資格、学校の案内 |
| 年収 | 源泉徴収票・給与明細の独自様式 | 職種別の平均年収の統計 |
| 家族構成 | 扶養控除申告書の続柄・生年月日、自由文 | 世帯数の統計、家族向け商品の案内 |
| 勤務先 | 社員証・名刺の見本、在籍証明書、「〇〇社に勤務」の自由文 | 会社概要、取引先一覧（個人の帰属なし） |

### 3.6 パスワードと一方向変換値

一方向変換値（ハッシュ）は、元に戻せない変換を施した値を指す。平文は試験専用の既知の文字列から作り、正解側に変換方式と元の値を保存する。

| 区分 | 陽性 | 陰性 |
|---|---|---|
| 平文 | 初期パスワード通知メール、設定ファイルの`DB_PASSWORD=`、Wi-Fi接続情報、アカウント台帳の表、URL内の`user:pass@`、コード中の文字列 | パスワード規則の説明、`********`や`<password>`等の伏字、入力画面の説明、注文番号等の無関係なランダム文字列 |
| 一方向変換値 | 塩なしのMD5・SHA-1・SHA-256（16進）、bcrypt、argon2id、scrypt、PBKDF2（Django形式）、sha512-crypt、NTLM、LDAPの`{SSHA}`、`/etc/shadow`の行、利用者表のデータベース出力 | ファイルのSHA-256チェックサム一覧、gitのコミット識別子、コンテナイメージの`sha256:`識別子、UUID |

SHA-256の16進文字列は、パスワード由来でもファイルの検査値でも形は同じである。そのため、方式の接頭辞で判別できるものと、文脈（列名・項目名）でしか判別できないものを`cue`で分けて採点する。`embedded.py`の変更用パスワードの値も、この区分の正解として登録する。

### 3.7 顔・音声・映像（存在の検知）

実在者を使わず、「誰か」ではなく「顔・声・話された個人情報が含まれるか」を正解にする。

| 媒体 | 生成方法 | 正解 | 陰性 |
|---|---|---|---|
| 顔画像 | 利用条件で生成物の配布を認める合成顔、またはイラスト・3D描画の顔。証明書見本・社員証・単独写真・集合写真へ配置 | 顔の位置矩形と数、証明書内か単独か | 風景、後ろ姿の人物、物体だけの写真 |
| 音声 | 利用条件が明確な日本語の音声合成で、架空の通話（氏名・カード番号・病歴の申告）を読み上げる。WAV・MP3・M4A | 文字起こしと各個人情報の発話区間 | 製品説明の読み上げ、無音、音楽 |
| 映像 | 個人情報を表示するスライド画面、合成音声、合成顔をMP4に組み合わせる。字幕トラックだけに個人情報を置く例も作る | 画面文字の出現時刻、発話区間、字幕の行 | 同じ構成で個人情報のない映像 |

容量の目安は、音声30本×60秒のWAVで約60MB、映像20本×30秒で約40MB、顔画像60枚で約30MB。現行の約128MBに加えてもLIGHTの上限660MB内に収まる。

Workspace DLPが音声・映像を検査しない場合は、観測を`unsupported`とし、見逃しに数えない。文字起こしや映像の文字認識を別に組み合わせる構成を評価する入口として使う。

## 4. 難しい項目

| 項目 | 難しい理由 | 代わりにできること |
|---|---|---|
| 実在者の顔・声による本人識別 | 実在者の顔・声を使えない。合成の人物には照合すべき本人がいない | 3.7の存在検知だけを評価する |
| 個人識別符号としての顔特徴量・声紋・指紋 | 符号は照合システム固有の数値配列で、内容だけでは生体由来か判定できない。正しい形式の符号も照合システムなしに作れない | `face_embedding`等の項目名付き数値配列で、項目名の検知だけを測る。本来の検知は評価しない |
| 写実的な合成顔 | 生成した顔が実在者に似ていないと保証できない。生成モデルごとに利用条件が異なる | LIGHTはイラスト・3D描画、写実はMEDIUM以降に利用条件と類似の確認手順を定めてから |
| 実物と同等の在留カード・保険証・免許証の画像 | 偽造・なりすましに転用できる | 独自様式の見本だけを作る。そのため実物画像への製品の分類精度は測れない |
| 法解釈が分かれる境界例 | 「異常なし」の健診結果、推知のみの情報、本人が公開した情報、統計化した情報等は、正解が法解釈に依存する | `certainty=判断保留`で作り、主指標から除いて別集計 |
| 「その他すべて」の網羅 | 要配慮個人情報は閉じた一覧だが、法定外の機微情報や業種別の規制は閉じた一覧がない | 法定区分と117項目の一覧を対象にし、追加分は版を分ける |
| 実在性・有効性 | 口座の実在、カードの有効性、パスワードが現役かは外部の事実が必要 | 形式と文脈の検知に限定する |
| 実務での誤検知率 | 合成資料の分布は実務と異なる | 対応範囲の確認と変更前後の比較に用途を限る |

## 5. 実装の順序

| 段階 | 内容 | 主な変更 |
|---|---|---|
| P0 | 要配慮個人情報の値と文脈の拡張、見出しなしの陽性、紛らわしい陰性、`legal_class`等の注釈、`embedded.py`の値の正解登録 | `generate.py`の`FIELDS`を値の候補群へ置換、比較資料にV09以降を追加 |
| P1 | 保険情報、在留カード・保険証の番号と見本、資産・勤務先、パスワードと一方向変換値 | 番号生成と見本様式の追加、認証情報用の生成部 |
| P2 | 合成顔、合成音声、映像 | 音声合成と映像合成の依存を固定し、媒体の検証部を追加 |

各段階で、既存の全件検証（形式・正解・配置・再生成の一致）に新しい種類を加える。`benchmark.py`の採点は`legal_class`と`certainty`で分けた集計を追加する。
