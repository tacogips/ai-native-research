# 日本の大型ランサムウェア・流出事案の深掘り

調査日：2026年10月8日。原資料は `research/disclosures/raw/incidents/japan_major_ransomware/`（Git管理外）に保存し、SHA-256一覧を同ディレクトリの `SHA256SUMS.txt` に置いた。既存調査で取得済みの資料は `research/disclosures/raw/personal_data_incidents_20261008/` を再利用した。攻撃者のリークサイト（盗んだデータを公開する攻撃者側のWebサイト）と流出データは閲覧・収集していない。

**調査上の制約：** 本調査の途中で、セッション共有のWeb検索回数の上限に達した。以降は各社・当局の公式サイトの一覧ページを直接たどって一次資料を取得した。このため、報道記事・裁判記録・警察発表の横断検索は十分にできていない。「未確認」と書いた項目の多くはこの制約による。

## 用語

| 用語 | 意味 |
|---|---|
| ランサムウェア | データを暗号化して使えなくし、復号や非公開と引き換えに金銭を要求する不正プログラム。近年は暗号化前にデータを盗み、公開すると脅す「二重恐喝」が多い |
| フォレンジック調査 | ログや機器の記録から、侵入の経路・時期・被害範囲を突き止める鑑識的な調査 |
| VPN | 社外から社内ネットワークへ安全に接続するための通信経路。機器の脆弱性や弱い認証があると侵入口になる |
| 多要素認証（MFA） | パスワードに加え、所持する端末や生体情報など異なる要素を組み合わせて本人確認する方式 |
| EDR／XDR | 端末やサーバーの不審な挙動を検知し隔離等へつなぐ仕組み（EDR）と、それを複数の領域へ広げた仕組み（XDR） |
| SOC | セキュリティ監視を常時行い、脅威を検知・対処する専門チーム |
| Active Directory | 社内の利用者アカウントや権限を一元管理する認証基盤。奪われると社内全体の権限が攻撃者に渡りやすい |
| 仮想化基盤・プライベートクラウド | 物理サーバー上で多数の仮想サーバーを動かす自社運用の基盤。基盤ごと暗号化されると上の多数のシステムが同時に止まる |
| WMS | 倉庫管理システム。物流センターの入出荷・在庫・自動設備を制御する |
| 3PL | 他社の物流業務を一括で受託するサービス |
| 特別損失 | 通常の営業活動以外で臨時に生じた損失として計上する費用 |
| 監査上の主要な検討事項（KAM） | 会計監査人が、その期の監査で特に重要と判断した事項を監査報告書に記載するもの |
| 発信者情報開示請求 | 匿名の投稿者を特定するため、SNS等の運営者に発信者の情報開示を求める法的手続 |
| 個人情報保護委員会（PPC） | 個人情報保護法を所管する国の機関。漏えい等報告を受け、指導・勧告・命令を行う |

## このグループの要点

- **4件とも、侵入の起点は「認証情報」か「境界の通信機器」である。** KADOKAWAは従業員アカウント窃取（フィッシング等と推測）、イセトーは更新されていないVPN機器と弱い管理者パスワード、アスクルは多要素認証の例外だった委託先の管理者アカウント、アサヒは拠点のネットワーク機器と弱いパスワードだった。
- **侵入後、共有データセンターや仮想化基盤の管理権限が奪われ、被害が事業全体へ広がった。** KADOKAWAは自社の基幹系が暗号化されていなくても、同じデータセンターの緊急停止で出版・経理が止まった。
- **バックアップは「ある」だけでは守れなかった。** アスクルは同じデータセンター内のバックアップも暗号化・削除された。ドワンゴは一部サービスのデータとシステムを失い、ニコニコミュニティを終了した。
- **ログの欠落で原因が確定できない事例が多い。** イセトーはVPN機器のログを取得しておらず、アスクルは委託先端末のOS更新で侵入時のログが消えた。
- **流出件数は公表後も変わる。** KADOKAWAは2024年8月の254,241人を11月に261,956人へ更新した。アサヒは2026年7月に当局との協議を踏まえ「おそれ」の範囲を約229万件へ広げた。
- **財務報告の遅延と監査上の論点が共通して生じた。** KADOKAWAは有価証券報告書の提出期限を延長した。アスクルは第2四半期決算を延期した。アサヒの2025年12月期決算の説明会は2026年7月9日までずれ込んだ。KADOKAWAとアスクルの監査報告書は本件を監査上の主要な検討事項とした。
- **確定した費用は、KADOKAWAの特別損失約24億円、アスクルの特別損失約51億円と休止資産の償却約13億円、アサヒの一時費用約170億円（概算）である。** 売上・利益の減少影響はこれと別に開示されている。
- **身代金支払いを会社が公式に認めた事例はない。** アスクルは攻撃者と接触せず交渉も支払いもしていないと明言した。KADOKAWAは支払いを報じた報道に抗議し、コメントしていない。
- **4件とも、一次資料でAIが攻撃や被害に関与したとする記載は確認できなかった。**

#### 3. 侵入経路と技術的原因

本節は、欠けていた統制と止められた箇所だけを書く（共通仕様の追加規則による）。

| 観点 | 一次資料で確認できること |
|---|---|
| 初期侵入で欠けていた統制 | 会社は経路と方法を「不明」としたうえで、従業員アカウントの認証情報の窃取（フィッシング等と推測）を根本原因とした。学園の発表は、窃取されたのは委託先ドワンゴの従業員アカウントと明記した。多要素認証の有無は公表されていない |
| 拡大を許した構造 | 1つのアカウントから社内ネットワークに入られ、グループ企業のデータセンター内のプライベートクラウドで「相当数の仮想マシン」が暗号化された。同じデータセンターを共有するKADOKAWAの基幹系も、緊急停止で巻き込まれた |
| 止められた箇所 | パブリッククラウド上のニコニコ動画のシステム・動画データ・配信システムは被害を受けなかった。クレジットカード情報は社内に保有しない設計で、流出しなかった。ニコニコ利用者のログイン情報の流出も確認されていない |
| 封じ込めの難しさ | 遠隔での停止だけでは攻撃の継続を止められず、会社は電源と通信を物理的に切断した。この結果、データセンター内のサーバーはすべて使用不可となった |
| 検知 | 会社は「時間をかけて計画的に攻撃を加えていると思わしき痕跡」を確認したと述べた。侵入から暗号化までの間に検知・遮断できなかったことになるが、検知体制の不備の内容は公表されていない |
| 公表されていない事項 | 侵入時期、権限の取得方法、持ち出しの経路と量、ランサムウェアの種類 |

二次分析（piyolog 2024-08-19）は、被害基盤をKADOKAWA Connectedのデータセンター上のプライベートクラウドと整理し、利用者アカウントを一元管理する認証基盤も攻撃者に掌握されたとしている。本調査では一次資料での明示を確認していない。

**攻撃者と犯行声明：** KADOKAWA・ドワンゴの公式資料は組織名を一度も記載していない。表現は「当該ランサムウェア攻撃を行ったとする組織」である。犯行声明はその組織がリークサイトで行い、会社が6月28日・7月2日・9月11日に「主張を確認した」と発表した。組織名を「BlackSuit」とする記述は解説記事等に見られるが、本調査では原報道も攻撃者側の声明も確認していない。

#### 9. 企業AI基盤への教訓（本調査の推論）

- **認証情報1つで基盤全体に届く構成を避ける。** 1人の従業員アカウントから仮想化基盤の多数の仮想マシンまで到達された。AIエージェントに与える資格情報も、対話用・ツール実行用・管理用を分け、管理用は人の承認と短命な発行に限るべきである。
- **共有基盤の「巻き添え停止」を設計で避ける。** KADOKAWAは暗号化されていない事業まで、同じデータセンターの緊急停止で止まった。AI基盤をグループ共通で運用する場合、隔離単位と停止単位を事業ごとに分けておく必要がある。
- **封じ込めは遠隔操作だけに頼らない。** 遠隔停止で攻撃を止められず、物理切断に至った。管理面（ハイパーバイザー管理、AI基盤の管理API）を通常ネットワークから分離し、緊急遮断の手順を別経路で持つべきである。
- **復旧点を決めておく。** 静画は5月23日のバックアップから、アカウントは6月7日以前の状態で復旧し、コミュニティはデータ消失で終了した。会話履歴・ベクトル索引・プロンプト設定などAI固有のデータも、復旧点と消失時の扱いを事前に決めておく。
- **委託関係を利用者に説明できるようにする。** 学園は「影響はない」と誤って説明した。AI処理を外部や子会社に委託する場合、どのデータを誰が処理しているかの台帳を公開説明に耐える形で持つべきである。
- **保存期限。** 元従業員・面接者・資料請求者の情報が大量に含まれた。AIの学習・検索用に集めた人事・顧客データも、目的終了後に削除する。
- **AIの関与：** 一次資料にAIが攻撃や被害に関与したとの記載はない。

#### 9. 企業AI基盤への教訓（本調査の推論）

- **作業用コピーが本番より弱い場所に置かれる。** 通知書データは管理区域では守られていたが、業務効率のためのコピーが別ネットワークにあり漏えいした。AIの評価用データ、プロンプトの検証ログ、RAG（検索拡張生成）用の抽出テキストも同じ構図になりやすい。原本と同じ区分で管理し、置き場所を機械的に制限すべきである。
- **ルールは明文化し、委託契約に書く。** 保管ルールが暗黙で契約にもなかった。AI処理の委託でも、保存場所・保存期間・削除証跡を契約と監査項目に入れる。
- **境界機器とログ。** 3年間更新されないVPN機器と、ログ未取得の組み合わせが原因究明を不可能にした。AI基盤のゲートウェイやAPIキー管理でも、更新とログの外部保存を義務化する。
- **委託先の事故は委託元の事故になる。** 41の委託元が通知を負った。AIサービスの提供者を選ぶ際、認証の取得だけでなく実際の運用（更新・ログ・データの所在）を確認する必要がある。

#### 9. 企業AI基盤への教訓（本調査の推論）

- **「例外」を棚卸しする。** 委託先の管理者だけMFAの例外になっていた。AI基盤でも、運用ベンダーやサービスアカウントの認証例外が侵入口になりやすい。例外には期限と承認者を付け、定期的に消す。
- **バックアップの管理権限と保管場所を本番から分ける。** 同じデータセンター内のバックアップが暗号化・削除された。モデル設定、プロンプト、評価データ、ベクトル索引のバックアップも、本番の管理者では消せない場所に置く。
- **監視対象の網羅。** 侵害されたデータセンターのサーバーにEDRがなかった。AI推論サーバーやエージェント実行環境が監視対象から漏れていないかを確認する。
- **SaaSへの連鎖。** 社内侵害から外部クラウドの問い合わせ管理システムへ広がった。AIエージェントが持つSaaS連携トークンは、社内侵害時に一括失効できるよう台帳化する。
- **物理設備に近いシステムの停止影響。** WMSの停止で自動倉庫全体が止まり、手作業へ切り替えた。AIが業務設備を制御する場合も、AI停止時の手動運用手順を用意する。
- **AIの関与：** 一次資料にAIが攻撃や被害に関与したとの記載はない。第3四半期決算短信の費用説明に「DX推進に伴う生成AI等のライセンス費用」と「ランサムウェア攻撃の対応費用」が並んで記載されているが、これは費用増の要因の列挙で、攻撃とAIの関係を示すものではない。

### 教訓（本調査の推論）

1. **認証情報と境界機器が入口であり続けている。** 4件とも、特殊なゼロデイ攻撃ではなく、窃取された認証情報、更新されない機器、弱いパスワード、MFAの例外から侵入された。AI基盤のAPIキー、エージェントのツール権限、管理コンソールも同じ入口になる。短命の資格情報、例外の期限管理、管理面へのフィッシング耐性のあるMFAを最初に整える。
2. **共有基盤は被害の単位を大きくする。** KADOKAWAは同じデータセンターの停止で暗号化されていない事業まで止まった。アサヒは約300拠点の回線を全て遮断した。AI基盤を全社共通にする場合、隔離と停止の単位を事業・データ区分ごとに設計する。
3. **バックアップは本番の管理者から切り離す。** アスクルのバックアップ削除、ドワンゴのデータ消失によるサービス終了が示すとおり、同じ権限で消せるバックアップは攻撃者にも消せる。
4. **ログが残らなければ原因も通知範囲も確定しない。** イセトーとアスクルは侵入方法を特定できず、アサヒは「おそれ」の範囲を広げた。AIの操作ログ・ツール呼び出しログも、実行環境の外へ改ざんできない形で送る。
5. **作業用コピーと保存期限が漏えい規模を決めた。** イセトーは規則外のコピー、KADOKAWAは元従業員・面接者・資料請求者の情報が大量に含まれた。PPCは2026年10月7日の注意喚起で、不要になった個人データの消去の徹底と、フィッシング耐性のあるMFA、ログの保護、侵害時の隔離等を技術的安全管理措置の手法例として先行提示した。AIの学習・検索用データにも同じ消去規律を適用する。
6. **委託の連鎖を説明できるようにしておく。** イセトーは41の委託元と約100団体に波及し、アスクルは3PL委託元のエンドユーザーに及び、学園はドワンゴへの委託を当初説明できなかった。AI処理の委託・再委託も台帳化する。
7. **財務報告と監査への影響を想定する。** 3社が決算・法定開示を延期し、KADOKAWAとアスクルでは監査法人がKAMとして復旧データの信頼性と内部統制の是正を検証した。AI基盤が会計・受発注に関わる場合、停止時の代替手順と記録の証跡を平時から用意する。
8. **AIの関与は4件とも一次資料で確認できない。** 本グループの教訓は、AIそのものより、AI基盤が既存の認証・ネットワーク・バックアップの弱点を引き継ぐことにある。
