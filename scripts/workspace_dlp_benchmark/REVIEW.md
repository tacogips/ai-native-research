# Google Workspace DLP試験の設計レビュー記録

レビュー日：2026年11月16日。DLPは機密情報の検知・保護、是正は検知後に共有の遮断や制限などで露出を止める処置を指す。

対象は[この試験の説明書](README.md)と`benchmark.py`、[画像・Office・PDF等の生成器](../pii_image_dataset/README.md)と`google_drive.py`、および[CLIとAPIの調査](../../research/technology/google_workspace_dlp_cli_api_deep_dive_20261111.md)等の関連文書。

**以下の指摘本文は修正前の静的レビュー記録である。** 原レビュー時点では生成器・採点・Google実環境の試験を実行しておらず、製品仕様も再確認前だった。状態列と末尾の対応記録を2026年11月16日に更新した。公開仕様の再確認と出典は[対応設計書](../../research/technology/workspace_dlp_benchmark_review_response_20261116.md)にまとめた。ローカル試験の成功とGoogle実環境での検証完了を区別する。

## 原レビューの判定

**現状は検知の試験設計だけで、是正の試験が存在しない。** 規則の動作は「監査のみ」で、採点も検知の有無の二値だけである。`google_drive.py`の権限付与・取消は所有者が自分で操作する読取確認で、DLPが共有を止めたかの検証ではない。設計文書も是正を初期版から外している。検知側にも、結果の解釈を誤らせる穴がある。

最初に対応するのは、検知試験の1〜4と是正の状態遷移表の5点。これらがないと、実測しても数値を解釈できない。

## 検知試験の問題点

重要な順に並べる。

| 番号 | 問題 | 内容と対応案 | 状態 |
|---|---|---|---|
| 1 | 未検知と未検査を区別できない | `not_detected`の根拠は人が書く`evidence`だけ。全ファイルの先頭と末尾に固有の文字列を入れ、それに反応する独自検知器の監査専用規則を並走させる。その記録があるファイルだけを検査済みと判定する | 実装・試験済み：先頭／末尾対照＋同一述語の否定、版・範囲・原票の照合。内部走査の直接証明ではない |
| 2 | 所有者が規則の適用範囲外になるおそれ | `google_drive.py`は`google.auth.default`で認証する。サービスアカウント（プログラム用の認証主体）が所有者になり、規則の適用範囲である組織部門・グループの外なら、全件が未検知に見える。所有者と適用範囲の一致を最初に確かめ、マイドライブと共有ドライブを分けて試験する | 実装・試験済み：配置前の実主体・所有者・共有ドライブ照合。適用範囲の証拠は別途必要、実環境未検証 |
| 3 | 各分類の値が1個だけ | 陽性10例は同じ値の文脈違いで、その値が弾かれると全滅する。検査数字（番号の誤りを検出するための末尾等の数字）が正しい値と誤った値を複数用意し、対にする | 実装・試験済み：7分類×6値。個人番号・カードの検査数字対。免許証の検査数字は未確認として保留 |
| 4 | 陰性が易しすぎる | 空欄・伏字・説明文だけで、数字列を含む紛らわしい例がない。偽陽性率はほぼ0になり、適合率が過大に出る。検査数字だけ誤った番号、12桁の注文番号、銀行の語を伴わない7桁、日付等を主試験に入れる | 実装・試験済み：注文番号・検査数字違い等を追加。意味が曖昧な正解を陰性へ補完しない |
| 5 | 見出しなしで値だけの陽性がない | 全陽性に分類名の見出しが付くため、文脈語への依存を測れない。値だけの例と見出し付きの例を対にする | 実装・試験済み：値だけ／見出しありを対にした |
| 6 | 他分類への誤反応を記録できない | 観測は「資料×対応する検知器」だけ。免許証と個人番号はともに12桁なので、資料×全規則の行列で記録する | 実装・試験済み：資料×全分類×閾値で保持。不明正解は採点対象外 |
| 7 | 閾値が1点だけ | 同じ検知器で確信度違いの監査専用規則を並べれば、1回のアップロードで閾値ごとの結果が取れる | 実装・試験済み：3閾値の計画。API設定の実適用・管理画面との対応は別検証 |
| 8 | 主指標に回避表現が混ざる | 評価集合の陽性8例のうち3例が全角・途中改行・ゼロ幅文字。基本の再現率と回避耐性を別の指標にする | 実装・試験済み：基本表記の評価TXTと回避表現を分離 |
| 9 | 検査の契機と遅延を測っていない | 新規作成、既存ファイルの編集、規則変更後の再検査を分け、アップロードから記録までの時間を取る。是正の露出時間の基礎になる | 一部実装：作成時刻区間、契機・記録時刻と遅延を保存。編集・規則変更の実測と時計差検証は未実施 |
| 10 | 手作業の工程が多い | 規則は管理画面で設定し、観測は手で記入する。規則はPolicy APIで定義から作成し、監査記録から観測表への変換を用意すれば再現できる。識別子はリポジトリ外に置く | 実装・試験済み：API新規作成→完了待ち→読み戻し、監査原票変換。変更・削除は未実装、実API未検証 |
| 11 | 拡張試験に採点経路がない | `benchmark.py score`は自前の`ground_truth.json`しか読めず、`pii_image_dataset`の`ground_truth/files.json`とは形式が違う。`benchmark.py`自体の試験もない | 一部実装：拡張正解の読込・採点と回帰試験を追加。既存画像等への検査対照の追加は未実装 |

## 是正試験として追加するもの

是正は「動作 × 事前の共有状態 × 操作者 × 契機」の状態遷移として設計する。結果は別主体（組織外のアカウント）の実アクセスで確認する。`google_drive.py`の`verify-granted`・`verify-revoked`の仕組みを流用できる。

| 確認点 | 見るもの | 状態 |
|---|---|---|
| 使える動作 | 外部共有の遮断・警告、閲覧者のダウンロード・印刷・コピー禁止、分類ラベル付与が契約版ごとに使えるか（要確認） | 公開仕様確認・計画／採点実装。契約版ごとの実利用は未検証 |
| 既存の共有 | 検知前に外部共有済みの利用者や、リンクを知る全員のアクセスが切れるか、新規共有だけ止まるか | 計画・証拠検証実装。既存の読取成功と別主体の事後読取を要求。実測未実施 |
| 露出時間 | アップロードまたは対象情報の追記から是正が効くまでの時間と、その間に外部から読めるか | 採点実装：最後の読取成功～最初の拒否の区間、打切り、再露出を区別。実測未実施 |
| 解除 | 対象情報を削除した後、規則を無効化・削除した後に、制限とラベルが戻るか | 計画・採点実装：本文修復／規則無効化／削除の根拠と解除区間を確認。実測未実施 |
| 迂回 | 編集者によるダウンロード、コピー、別形式への書出し、共有ドライブへの移動、所有者の変更、Apps Script・外部アプリ経由 | 試験行を追加。経路別の操作・証拠収集の実装は一部未対応、実測未実施 |
| 競合 | 複数規則が一致したときの優先と`suppressed_actions`の記録 | 計画と動作／抑制記録の検証を追加。期待結果の事前固定と実測は未実施 |
| 過剰な是正 | 陰性資料や業務上許可した資料が遮断される割合 | 計画・採点実装：陰性は原票で評価完了を確認し、無記録を成功にしない。実測未実施 |
| 利用者側 | 警告の表示、警告を無視した共有の記録、所有者への通知、誤検知の申立て経路の有無（要確認） | 公開仕様と計画を追記。警告の証拠を採点するが、画面収集・通知／申立て経路の実測は未実施 |

指標は、是正の成功率、是正までの時間、残存した外部権限の数、過剰遮断率、解除の成否とする。

## 他の方法

いずれも候補であり、採用を決めたものではない。

| 方法 | 利点 | 注意点 |
|---|---|---|
| GmailやChatのDLPで検知器の特性を先に調べる | Driveは規則の反映に最大24時間かかる。即時に結果が出る経路で値や文脈の反応を絞り込み、Driveで本試験をする | 同じ検知器が同じ挙動かは要確認 |
| Google CloudのSensitive Data Protection検査APIを比較対象にする | 箇所と確信度が即時に返るので、データセットの値の選別に使える | Workspace DLPとは別製品。結果の一致を仮定しない |
| 分類ラベル経由の二段構成 | DLPはラベル付与だけにして、共有制限はラベル条件の規則や信頼ルールに任せる。是正の解除や例外を扱いやすい | ラベル自体が検査対象や規則条件になり得る |
| 自作の是正 | 監査記録を取得し、Drive APIで権限削除や隔離用フォルダーへの移動をする。標準動作と露出時間・既存共有の扱いを比較できる | 原本への変更権限が必要。設計文書では初期版の対象外 |
| 記録の取得経路を変える | Reports APIの定期取得のほかに、監査記録のBigQuery書出しや調査ツールがある | 契約版は要確認 |
| Drive以外の持出し経路を範囲に入れる | Drive DLPが扱うのは共有。ブラウザー経由のダウンロードや貼付けはChrome側のDLPやアクセス制御の範囲 | 試験範囲に入れるかを先に決める |

## 対応後のローカル検証記録（2026年11月16日）

次の検証は独自の架空資料と模擬API応答によるものである。Googleの実アカウント・実設定・実測値は用いていない。

- `python3 -m unittest discover -s scripts/workspace_dlp_benchmark -p 'test_*.py'`：144件成功。生成・検査数字・規則計画と通信境界・原票の照合・採点・是正の証拠検証を含む。
- `python3 -m unittest discover -s scripts/pii_image_dataset -p 'test_google_drive.py'`：必要ライブラリーを備えた一時環境で28件成功。配置前の範囲確認、読取専用の別主体確認、所有者による取消との区別を含む。実API通信なし。
- CLIを別プロセスで実行し、`make`で738資料・42値、`plan-rules`で46資源・21分類閾値組、`apply-rules`の既定実行で`dry_run`かつ通信0回、`plan-remediation`で196状態遷移を確認した。
- `import-audit`→`score`のCLI試験は、原票・設定の読み戻し・範囲証拠を備えた合成例で確認した。手書きの判定だけ、異なる顧客・版・内容、対照だけの成功、不完全なページ取得を実測精度に変換しない。

[実装の説明と実行手順](README.md)、[是正の状態遷移表と公開仕様](../../research/technology/workspace_dlp_benchmark_review_response_20261116.md)に対応範囲を記載した。`google_drive.py`の手動権限取消は引き続き所有者操作の確認であり、DLPの成功には算入しない。別認証による読取専用観測を追加したが、画面警告・印刷・コピー・通知等の全経路を自動収集する実装ではない。

規則の新規作成を実行する経路はあるが、今回の確認は通信しない実行と模擬応答に限る。既存規則の変更・削除、自作の権限取消による是正、全形式への検査対照の埋込みは未実装である。適用範囲の証拠は操作者が別途取得し、実主体との一致を検証する。Drive APIだけから組織部門・グループへの規則適用を独立判定してはいない。

実環境での規則適用、再走査、既存共有遮断、解除、通知、契機ごとの遅延は未検証である。このため製品のrecall・accuracy・F1や是正成功率の数値は提示しない。試験用の合成観測で計算できた指標を製品の実測値として扱わない。

原レビューの候補表は当時の記録として残す。現在の公開仕様では、Chatは走査の時間切れがあり即時の検査完了を保証できず、Drive DLPにも取得・印刷・コピー制限がある。「即時の経路」「Driveは共有だけ」という一般化は採用しない。根拠と制約は対応設計書を参照する。

### 独立再レビューで追加した修正

是正の共有状態・操作者・契機を計画の識別子だけで選べたため、一つの成功証拠を別の組合せへ流用できる問題も修正した。現在は別保存の`case_context`と、事前の完全な権限記録・操作契機の記録を照合する。条件を裏付けられない試行は`pending`（未判定）へ残す。

操作契機の実収集・照合アダプターは未実装である。現時点で最終判定する是正の例は`synthetic_fixture`（独自の合成証拠）に限り、結果へ`evidence_domain=synthetic`を付ける。これは採点コードの検証であり、製品の成功率ではない。未判定の計画を分母から落とさず、製品実測の成功率は算出しない。ファイル指紋と宣言はローカル証拠の一致確認であり、真正性の署名ではない。

特に新規作成・新規共有の遮断は、既存資料の事前可読性を使う現在の証拠経路だけでは完了できない。作成・共有試行専用の対照と記録収集が必要であり、未対応を製品の検知失敗・是正失敗に換算しない。

最終再実行では比較試験144件・Drive操作28件がすべて成功した。期待結果の既定値（遮断成功なら拒否等）の異なる値への上書きも拒否する。是正の196件を未実行のままCLIで採点し、判定済み0件・成功率`null`（算出不能）を確認した。独立再レビュー→修正→再試験を実施し、製品実測を行ったとは扱っていない。
