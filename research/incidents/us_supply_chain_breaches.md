# 米国中心のサプライチェーン・委託先経由の大規模事案

本書は、既存資料 `research/technology/personal_data_incidents_postmortem_20261008.md` の F07、F08、F15、F16、A01 節と、`research/technology/ransomware_damage_and_ai_era_trends_20261008.md` の Change Healthcare 記述を、一次資料で深掘りしたものである。調査日は2026年10月8日である。取得した原本は Git 管理外の `research/disclosures/raw/incidents/us_supply_chain/` に保存した。既存調査で保存済みの原本は `research/disclosures/raw/personal_data_incidents_20261008/` と `research/disclosures/raw/ransomware_20261008/` を参照した。攻撃者のリークサイトや流出データそのものは閲覧していない。

用語を先に定義する。

- **サプライチェーン経由の侵害**：自組織ではなく、委託先・製品提供者・クラウド基盤など外部の当事者の弱点を通じて自組織のデータが盗まれる事案。
- **多要素認証（MFA）**：パスワードに加えて端末の確認などの別要素を求める本人確認。
- **ゼロデイ脆弱性**：製品提供者が修正を出す前に悪用される欠陥。
- **SQLインジェクション**：入力欄などにデータベース命令を混ぜ込み、本来できない読み書きをさせる攻撃手法。
- **情報窃取型マルウェア（infostealer）**：感染端末からブラウザ保存のパスワード等を抜き取る不正プログラム。
- **ヴィッシング（vishing）**：電話で社員等をだまし操作させる手口。
- **MDL（multidistrict litigation）**：米国連邦裁判所で、各地に起こされた同種の訴訟を公判前手続のため1人の裁判官にまとめる制度。
- **8-K／10-K／10-Q**：米国上場会社が証券取引委員会（SEC）に出す臨時報告書／年次報告書／四半期報告書。

## このグループの要点

- 5件とも「自社の中核システムの欠陥」ではなく、**外部製品・委託先・クラウド利用者側の設定と認証情報**が入口になった。MOVEitは製品のゼロデイ脆弱性、Change HealthcareはMFAのない遠隔接続入口、Qantasは委託先担当者への電話誘導と顧客管理製品の初期設定、PowerSchoolは委託スタッフの保守用認証情報、TicketmasterはMFAのないクラウドデータ基盤の利用者アカウントである。
- 被害規模の一次資料上の最大値は Change Healthcare の約1億9,270万人（2025年7月31日に同社がHHSへ報告）である。MOVEitとTicketmasterは、全体の一意人数を確定した一次資料がない。
- **身代金の支払い**は、Change Healthcare（2,200万ドル、2024年5月1日の上院財政委員会でCEOが答弁）とPowerSchool（金額非公表、同社が2025年5月に公表）で一次資料により確認できた。いずれも支払い後にデータの再恐喝が起きたことが一次資料に記されている。
- 費用は桁が大きく異なる。UHGは2024年に直接対応費22.23億ドルと事業中断影響8.67億ドルを計上し、2025年第4四半期に医療機関向け貸付等の回収見込み悪化として7.99億ドルの引当金を積み増した。Progressの純費用は2026年8月までの累計で約1,600万ドル（本調査の合算）、Maximusは約3,520万ドル（同）である。Live NationとQantasは事案別の費用を開示していない。
- 法的手続は2026年10月時点で多くが継続中である。Change HealthcareとMOVEitのMDLは証拠開示の段階で、和解は公表されていない。刑事では、PowerSchool事案の被告人に合計48か月の拘禁刑と約1,406万ドルの賠償命令が出た。Snowflake顧客環境事案の被告人は2026年8月5日に有罪答弁し、量刑は2027年1月27日の予定である。
- 規制当局の判断は分かれた。豪州OAICはQantasに本格調査を開始しない判断を示した。カナダOntario州IPCはPowerSchoolを使う学校側の契約・監督・保存の不備を認定した。米国HHS OCRのChange Healthcare調査は結論が公表されていない。
- 企業AI基盤への示唆として、**外部接続の承認権限、保守用の常時接続、長期有効な認証情報、ログ保存期間、委託先の監督**が、AIエージェントや外部AIサービスとの接続でも同じ形で弱点になる（本調査の推論）。5件のいずれでも、AIが攻撃や被害に関与したことを示す一次資料は見つからなかった。

#### 3. 侵入経路と技術的原因

欠けていた統制と、止められた箇所の水準で記す（攻撃手順の詳細は扱わない）。

- **欠けていた統制（確定）**：インターネットに公開されたファイル転送製品に、認証なしで悪用できる未公表の欠陥（CVE-2023-34362。修正済み）があった。利用者側では修正前に防ぐ手段がなく、製品を外部に公開していたこと自体が入口になった。
- **被害の範囲を決めた要因（当局の記載）**：CISA・FBI によれば、攻撃者は転送サーバー上に不正な遠隔操作の仕組みを置き、サーバー内に保管されたファイルを持ち出した。サーバーに保管されていたファイルの量と期間が、そのまま被害の量になった。
- **止められた箇所（被害組織の主張）**：Maximus と Louisiana 州は、転送サーバーの外の社内システムへの広がりは確認されなかったと述べた。転送サーバーが社内網から分けられていたことが、被害をデータ持ち出しにとどめた要因と読める（本調査の推論）。
- **攻撃者の特定**：CISA・FBI は CL0P が犯行を主張していると記載した。Louisiana 州も CISA を引用して同様に述べた。
- **更新怠慢か否か（食い違いあり）**：Louisiana 州 FAQ は、OMV が当時最新の版を使っていたと述べ、修正の公表日を6月2日とする。Progress の 8-K は修正公開を5月31日とし、NVD は州が挙げた版番号を最初の修正版として記載する。本調査ではこの差を解消できなかった。

#### 9. 企業AI基盤への教訓（本調査の推論）

- **隔離**：外部とファイルをやり取りする中継サーバーは、最新版でも未知の欠陥で突破されうる。中継サーバーには処理中のファイルだけを置き、処理後に消す。AI基盤でも、外部AIサービスとの受け渡し領域を同じ扱いにする。
- **権限分離**：一つの欠陥で転送サーバー内の全ファイルに届いた。受け渡し領域ごとに暗号鍵と利用者を分け、一つの欠陥で全取引先の資料に届かない設計にする。
- **委託先管理**：Maximus のように、委託された政府業務の個人情報が委託先の製品で漏れる。発注側は、委託先が使う転送製品と保存期間を契約で把握する。
- AIの関与は一次資料で確認できなかった。

#### 3. 侵入経路と技術的原因

欠けていた統制と、止められた箇所の水準で記す（攻撃手順の詳細は扱わない）。

- **欠けていた統制（会社が認めた事実）**：遠隔デスクトップ用の入口（Citrix）にMFAがなく、盗まれた認証情報だけで接続できた。CEOは上院で、UHG の方針は「外部向けシステムにMFA」だったが、買収した子会社のこのサーバーには適用されていなかったと述べた。
- **認証情報の管理（州の主張）**：Nebraska 州司法長官は、低位のカスタマーサポート担当者の認証情報が外部の売買の場に出回っていたと主張する。MDLの判決文は、入手経路自体は不明と注記する。
- **検知できなかった段階（州・原告の主張）**：州司法長官と原告は、侵入から暗号化までの9日以上、権限の高いアカウントの作成や大量のデータ持ち出しが検知されなかったと主張する。会社の証言は「横に移動し、データを持ち出した」との記載にとどまる。
- **原告が挙げる管理不備（主張であり認定ではない）**：MFAの欠如、保存データの未暗号化、内部監視の不足、ネットワーク分離の欠如、最小権限の未実施である。裁判所はこれらを請求棄却申立ての判断のため事実と仮定して扱った。
- **止められた箇所（会社の説明）**：UHG は Change のデータセンターとの接続を直ちに遮断し、Optum や UnitedHealthcare など他の事業への広がりはなかったと述べた。一方、攻撃は本番系と予備系の双方に及び、旧式データセンター部分の復旧が難しかったとCEOは証言した。
- **攻撃者**：会社は ALPHV または BlackCat を名乗る者と述べた。当初の 8-K は「国家関与が疑われる」と記載したが、その後の開示では「サイバー犯罪の脅威主体」と表現を変えた。

#### 4. 影響

- **個人**：会社は医師のカルテや全診療歴の持ち出しは確認していないと述べた。州司法長官は、社会保障番号、運転免許番号、健康保険情報、医療記録、請求情報などを含むと主張した。人数は2024年7月の500人（仮置き）から、2024年10月の通知1億件、2025年1月の約1億9,000万人、2025年7月の約1億9,270万人へと更新された。
- **医療機関・薬局**：Change Healthcare は米国の医療支払の約6%を処理していた（CEO証言）。請求・支払・事前承認が止まり、Nebraska 州は地方の重要病院の資金繰り悪化を指摘した。UHG は2024年末までに90億ドル超の無利子貸付を医療機関に行った。
- **契約上の単一依存**：CEOは上院で、旧来の Change Healthcare 契約の一部に他社の利用を禁じる排他条項があったと認め、相手方を条項から解放すると答弁した。

#### 9. 企業AI基盤への教訓（本調査の推論）

- **認可と資格情報管理**：方針上は外部向けMFAが必須でも、買収した子会社の古い入口一つが例外として残った。AIエージェントの外部接続口や管理画面も、方針ではなく実在する全入口の棚卸しで確認する。
- **監査記録と検知**：管理者アカウント作成から暗号化まで9日間気づかれなかったとされる。AI基盤では、権限付与と大量取得を即時に警告する仕組みが必要である。
- **復旧**：本番系と予備系が同時に暗号化された。AI基盤のモデル設定・検索索引・権限設定も、切り離した予備を持つ。
- **委託先管理と単一依存**：医療機関は Change Healthcare 一社に請求・支払を頼っていた。AI処理を一社に集中させる場合も、停止時の代替経路を契約と運用で用意する。
- **通知責任**：HHS は、受託者が漏らしても通知の最終責任は委託元にあると示した。AI処理を外部委託しても、委託元の説明責任は残る。
- AIが攻撃や被害に関与したことを示す一次資料はない。UHG の10-K FY2025 は一般的なリスクとして生成AIによる攻撃の高度化に触れるが、本件との関係は述べていない。

#### 3. 侵入経路と技術的原因

欠けていた統制と、止められた箇所の水準で記す（攻撃手順の詳細は扱わない）。

- **欠けていた統制（OAIC の評価）**：委託先コンタクトセンターの一般担当者が、電話で社内IT支援を装った者にだまされ、外部アプリを顧客管理基盤に接続する承認を与えてしまった。製品の初期設定が、一般利用者による外部アプリ接続の承認を許していた。役割に応じた閲覧制限はあったが、接続されたアプリは担当者の閲覧範囲をそのまま取得できたため、防げなかった。
- **研修の限界（OAIC の評価）**：一般的な研修は認証情報の詐取への警戒が中心で、正規の画面操作で接続を承認させる手口は扱わないことが多いとした。
- **止められた箇所（OAIC）**：異常なログイン失敗の警告を2日後に職員が見つけ、当該アカウントを凍結して封じ込めた。カード、旅券、パスワードは当該基盤に保存されておらず、被害の範囲外だった。
- **製品側の是正（OAIC）**：製品提供者が、外部アプリ接続に関する初期設定を全顧客向けに変更した。
- **製品名と攻撃者**：OAIC と Qantas は製品名を挙げない。製品を特定する記述と攻撃者集団への帰属は、本調査で取得した一次資料にはない。Google は、同時期に顧客管理製品の利用者を電話で誘導して接続アプリを承認させる活動を報告し、製品基盤の欠陥ではなく利用者を操る手口だと述べた。Qantas と Google 報告の活動を一次資料で結び付ける記述は見つからなかった。

#### 9. 企業AI基盤への教訓（本調査の推論）

- **承認権限**：一般担当者が外部アプリの接続を承認できた。AIエージェントや外部AIサービスへの接続（OAuth の同意など）も、一般利用者の承認だけで有効にしない。管理者の事前許可リストに限る。
- **隔離と取得量の制限**：抽出ツールは担当者の閲覧権限の範囲を一括取得した。画面閲覧の権限と一括取得の権限を分け、件数の上限と警告を置く。
- **委託先管理**：OAIC は委託先の監査と研修を確認したうえで、それでも防げなかったと評価した。研修より、技術的に承認できない設計が効く。
- **監査記録**：検知のきっかけはログイン失敗の警告だった。接続アプリの新規承認自体を警告対象にする。
- **データ保持**：カード情報や旅券情報を顧客管理基盤に置いていなかったため、被害の深刻度が下がった。AIの作業領域にも不要な機微情報を置かない。
- AIの関与は一次資料で確認できなかった。

#### 3. 侵入経路と技術的原因

欠けていた統制と、止められた箇所の水準で記す（攻撃手順の詳細は扱わない）。

- **欠けていた統制（CrowdStrike と IPC）**：委託スタッフ（米国外で技術支援に従事）の、権限の高い保守用認証情報が使われた。保守用サポート基盤 PowerSource の接続にMFAがなかった。PowerSchool は IPC に、PowerSource がMFAに対応しない旧基盤だったと説明した。SIS 側にはMFAがあった。
- **顧客側の設定（IPC）**：学校側が遠隔保守接続を「常時有効」にしていたため、一つの保守用認証情報で多数の学校の SIS に届いた。
- **被害の範囲（CrowdStrike）**：取得は生徒表と教員表に限られ、システム層への侵入や不正プログラムの痕跡はなかった。
- **検知の遅れ（IPC）**：8～9月の不審な接続はログ保存期間を過ぎて監査記録が残っていなかった。IPC は8月から12月28日まで4か月、さらに12月の9日間、不正活動が検知されなかったことを「特に懸念」と述べた。検知のきっかけは攻撃者からの身代金要求だった。
- **認証情報の入手経路**：一次資料では不明である。
- **8月の活動の帰属（食い違い）**：CrowdStrike は8～9月の活動を12月の攻撃者に結び付けられないとした。連邦地検の起訴状は、被告人が9月4日に同じ認証情報で不正に接続しデータを得たと記載し、被告人は有罪答弁した。

#### 3. 侵入経路と技術的原因

欠けていた統制と、止められた箇所の水準で記す（攻撃手順の詳細は扱わない）。

- **欠けていた統制（Mandiant の攻撃群全体の分析）**：情報窃取型マルウェアで盗まれた Snowflake の利用者認証情報が使われた。Mandiant は3つの要因を挙げた。被害アカウントにMFAがなかったこと、何年も前に盗まれた認証情報が変更されず有効だったこと、接続元を信頼できる場所に限る設定がなかったことである。Snowflake 自体の侵害の証拠はないとした。
- **委託先端末（Mandiant）**：いくつかの事例で、最初の感染は請負業者の端末で起きていた。その端末は私用にも使われ、管理されていなかった。
- **検知できなかった段階**：起訴状によれば、Victim-4 の環境への不正アクセスは約5週間続いた。大量取得の段階で検知・遮断された記載は一次資料にない。

### 企業AI基盤への教訓（本調査の推論）

1. **接続の承認を一般利用者に任せない。** Qantas の経路は、AIエージェントに外部ツールを接続する同意操作と同じ形をしている。接続先は管理者の許可リストに限る。
2. **保守・運用の権限は依頼ごとに時間を区切る。** PowerSchool の常時接続は、AI基盤の運用者や外部ベンダーの保守接続にもそのまま当てはまる。
3. **長期有効な認証情報をなくす。** Snowflake 顧客環境では数年前の認証情報が使われた。AIの API キーとサービスアカウントにも期限と自動更新を設ける。
4. **受け渡し領域は「いつか破られる」前提で小さくする。** MOVEit は最新版でも突破された。外部AIとの受け渡しには、処理中のデータだけを置く。
5. **一括取得を監視する。** データ基盤からの大量書き出しや外部アプリによる一括取得は共通の兆候である。AIによる検索・要約の一括処理にも件数上限と警告を置く。
6. **委託しても説明責任は残る。** HHS は通知の最終責任を委託元に置き、Ontario 州 IPC は学校側の契約と監督の不備を認定した。外部AIサービスとの契約にも、監査資料の取得、MFA、ログ保存、終了時削除を入れる。
7. **代替経路を持つ。** Change Healthcare への単一依存が医療の支払を止めた。AI処理を一社に集中させる場合も、停止時の手作業や別経路を用意する。

5件のいずれでも、AIが攻撃や被害に関与したことを示す一次資料は確認できなかった。
