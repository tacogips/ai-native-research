# AX Criteria 設問50項目・採点基準・用語集・ガイドの内容記録

取得したJSON原本はGitで管理しない。本資料は公開API（ログイン不要）から2026年10月6日に取得した内容を、情報を落とさずに記録したものである。設問・採点基準・用語・ガイドの文章は日本CTO協会の著作物であり、CC BY-SA 4.0 に基づいて出典を示して転記する。各項目の解説文（サイト上の `has_doc`）と会員向けAPI（`/api/criteria`、401）は取得していない。対応関係の分析は[AX Criteriaとの対応表](../strategy/ax_criteria_crosswalk.md)にある。

## 1. 共通の採点尺度（generic_score_guide）

| Score | 定義（原文） |
|---|---|

| 0 | 取り組みがない。話題にも上がっていない |
| 1 | 必要性は認識され、議論や個人的な試行が始まっている |
| 2 | 一部の部門・業務で試験的な取り組みが動いている |
| 3 | 主要な範囲で仕組みとして導入・運用されている |
| 4 | 制度・文化として定着し、継続的な記録と改善が回っている |

項目ごとに固有の採点基準（Score Guide）があり、実際の判定ではそちらを使う。ガイドは「Score 4でAIによる自律化を問う項目もあり、すべてを単に『定着しているか』だけで判定しない」と注記する。

## 2. 設問50項目と項目別採点基準（原文）

### 1. Strategy (経営戦略・価値再配置)

#### サブテーマ: 経営の認識更新

**1.1** 経営陣がAIエージェントを日常業務で使い、その経験をAI活用への投資、組織づくり、業務設計の判断に生かしている。

| Score | 判定基準 |
|---|---|
| 0（使用していない） | 経営陣はAIエージェントを日常業務で使っていない |
| 1（一部の役員が試している） | 一部の役員がAIエージェントを個人的に試しているが、その経験は経営陣で共有されていない |
| 2（利用経験を共有している） | 複数の役員がAIエージェントを限られた業務で継続利用し、利用経験を経営陣で共有している。ただし、AI活用への投資、組織づくり、業務設計の判断には生かしていない |
| 3（AI活用の判断に生かしている） | 経営陣の大半がAIエージェントを日常業務で継続利用し、その経験をAI活用への投資、組織づくり、業務設計の判断に生かしている。AIエージェントの利用経験を踏まえて、どのような経営判断をしたかを記録している |
| 4（利用経験と経営成果を検証している） | AIエージェントの利用経験をもとに行ったAI活用の判断について、期待した効果と実際の事業成果を比較している。効果が確認できた使い方を、他の経営業務や判断へ展開している |

**1.2** 顧客や市場の変化と事業の実行状況をAIエージェントで継続的に分析し、戦略や施策を見直す仕組みがある。

| Score | 判定基準 |
|---|---|
| 0（状況を把握していない） | 顧客や市場の変化、事業の実行状況を、AIエージェントでも人手でも継続的に把握できず、戦略や施策を見直していない |
| 1（必要時に人が分析している） | AIエージェントは使わず、必要になったときに人が情報を収集・分析しているが、見直しは個別対応に依存している |
| 2（部門や担当者が個別に利用している） | 一部の部門や担当者が、顧客や市場の変化、事業の実行状況をAIエージェントで個別に分析し、判断に利用している。ただし、診断対象の組織として継続的に運用している状態ではない |
| 3（継続分析を見直しに反映している） | 診断対象の組織として、顧客や市場の変化と事業の実行状況をAIエージェントで継続的に分析し、その結果を戦略や施策の見直しに利用している。判断と実施結果が記録されている |
| 4（AI分析の仮説と方法を更新している） | AIエージェントによる分析と見直しの結果を次の分析に反映し、経営上の仮説や観測指標、分析方法そのものを継続的に更新している |

#### サブテーマ: コスト削減と価値向上

**1.3** AIエージェントによる業務効率化を、人員配置や外部支出の見直しなど、費用構造の改善につなげている。

| Score | 判定基準 |
|---|---|
| 0（効果を把握していない） | AIエージェントによる業務効率化の効果を把握していない |
| 1（効果を把握している） | 業務効率化の効果は把握しているが、費用構造の改善にはつながっていない |
| 2（一部業務で費用を改善している） | 一部の業務で、AIエージェントによる効率化を費用構造の改善につなげている |
| 3（主要業務で費用を改善している） | AIエージェントによる効率化の影響が大きい主要な業務で、効率化を費用構造の改善につなげている |
| 4（費用構造の改善を経営指標で確認している） | AIエージェントによる効率化を主要な業務の費用構造改善につなげ、その効果を経営指標で確認し、予算や業務体制の変更として定着させている |

**1.4** AIエージェントによる業務効率化で生まれた余力を、顧客価値や事業成長へ再配分している。

| Score | 判定基準 |
|---|---|
| 0（余力を把握していない） | 業務効率化で生まれた余力を把握していない |
| 1（余力を把握している） | 業務効率化で生まれた余力は把握しているが、再配分先を定めていない |
| 2（一部施策で再配分している） | 一部の施策で、業務効率化で生まれた余力を顧客価値や事業成長へ再配分している |
| 3（全社または事業部で再配分している） | 全社または対象事業部で、業務効率化で生まれた余力を顧客価値や事業成長へ再配分している |
| 4（事業成果に応じて再配分している） | 全社または対象事業部で行った再配分の顧客価値や事業成果を確認し、その結果に基づいて配分先や配分量を再び変更している |

#### サブテーマ: 顧客価値と事業変容

**1.5** AIエージェントの普及による顧客・競争の変化を踏まえ、提供価値、勝つ領域、やらないことを定め、製品・投資・組織の優先順位に反映している。

| Score | 判定基準 |
|---|---|
| 0（事業上の選択がない） | AIエージェント活用が社内効率化だけで語られ、対象顧客や提供価値を決めていない |
| 1（アイデアを並べている） | AIエージェントを使った事業やサービスのアイデアはあるが、対象顧客と解く課題を決めていない |
| 2（候補を絞り込んでいる） | 顧客価値の仮説を検証し、注力する候補を絞り込んでいるが、勝つ領域とやらないことを経営として決めていない |
| 3（勝つ領域を決めている） | 対象顧客、提供価値、勝つ領域、やらないことを経営として具体的に定め、製品・投資・組織の優先順位に反映している |
| 4（事業成果に基づき選択を変えている） | 対象顧客、提供価値、勝つ領域、やらないことを経営として定めたうえで、選んだ領域の事業成果と競争環境を確認し、製品・投資・組織について継続、集中、縮小、撤退の判断を実行している |

**1.6** 顧客価値を実現するため、中核事業そのものをAIエージェント前提に再設計している。

| Score | 判定基準 |
|---|---|
| 0（効率化にとどまる） | AIエージェントを既存業務の効率化ツールとして使うだけで、事業やサービスの再設計を考えていない |
| 1（再設計の必要性を認識している） | AIエージェント前提で作り直す必要性は認識しているが、対象、計画、責任者が定まっていない |
| 2（周辺業務で試している） | 周辺業務や一部の顧客接点で再設計を試しているが、中核事業・主力サービスには及んでいない |
| 3（中核事業を再設計・移行している） | 選んだ顧客価値を実現するため、中核事業について、主力サービス・主要業務・組織の必要な範囲を一体として再設計し、移行と運用を始めている |
| 4（中核事業を継続的に改善している） | 再設計した中核事業が運用され、AIエージェントが顧客の反応と事業成果から改善点を示し、承認された変更をサービス・業務・組織へ継続的に反映している |

#### サブテーマ: 投資配分と撤退

**1.7** AIエージェントへの投資を主な目的で整理し、既存事業の強化と新しい価値の探索へ予算と人員を配分している。

| Score | 判定基準 |
|---|---|
| 0（投資全体を把握していない） | AIエージェントへの投資が案件ごとの判断に任され、投資全体の構成を把握していない |
| 1（既存事業の強化に偏っている） | 既存事業の強化に偏り、新しい価値の探索に充てる予算や人員が確保されていない |
| 2（投資を主目的で整理している） | AIエージェントへの投資を主目的に沿って整理しているが、配分の見直しは個別判断に依存している |
| 3（戦略に基づき資源配分している） | AIエージェントへの投資全体について、既存事業の強化と新しい価値の探索の主目的を把握し、戦略上の優先度に基づく予算や人員の配分と、その理由を記録している |
| 4（成果に応じて投資配分を変えている） | 既存事業の強化と新しい価値の探索に、戦略上の優先度に基づいて配分した予算・人員を、成果と市場変化に応じて増減し、投資全体の構成を変更している |

**1.8** AIエージェントに関する施策ごとに継続・拡大・停止の条件を定め、定期的に見直している。

| Score | 判定基準 |
|---|---|
| 0（判断条件がない） | AIエージェントに関する施策を始めた後の判断条件がなく、成り行きや担当者の判断で続いている |
| 1（条件設定の必要性を認識している） | 継続や停止の条件を定める必要性は認識しているが、判断時期や責任者が決まっていない |
| 2（一部施策に条件がある） | 一部のAIエージェントに関する施策で条件と判断時期を定めているが、共通の運用にはなっていない |
| 3（条件に基づき判断している） | 事前に定めた条件に基づいて継続、拡大または停止を判断し、理由と必要な資源再配分を記録している |
| 4（判断条件を次の投資に反映している） | 複数の施策について継続・拡大・停止の判断結果を比較し、得られた成果や学習から判断条件を改定して、次の施策の設計と投資判断に適用している |

#### サブテーマ: 変革責任と全社連携

**1.9** AIエージェント変革を担う役員が明確で、成果目標を持ち、関係部門の責任者を通じて現場の実行を指揮している。

| Score | 判定基準 |
|---|---|
| 0（担当役員がいない） | AIエージェント変革を担う役員が定まっておらず、推進部門や個別事業部がそれぞれ施策を進めている |
| 1（担当役員を置いている） | 担当役員は定まっているが、具体的な事業成果目標や関係部門の実行責任が定まっておらず、名目的な担当にとどまっている |
| 2（推進部門を指揮している） | 担当役員が成果目標を持ち、推進部門の活動を指揮しているが、関係部門の実行責任が定まっておらず、現場の実行は依頼や自主的な協力に依存している |
| 3（関係部門を通じて現場を動かしている） | 担当役員が成果目標を定め、関係部門の責任者に実行責任を割り当て、その責任者を通じて現場の優先順位と実行を指揮している |
| 4（成果から目標と実行を見直している） | 担当役員が事業成果と現場からの情報を確認し、成果目標、関係部門の実行責任、現場への指揮の方法を継続的に見直している |

**1.10** 全社と事業部が、AIエージェント変革に関する共通の目標と実行計画に基づいて進捗を確認し、優先順位を継続的に調整している。

| Score | 判定基準 |
|---|---|
| 0（全社と事業部で確認する場がない） | 全社と事業部でAIエージェント変革の目標や進捗の捉え方が異なり、相互に確認する場がない |
| 1（全社と事業部の計画が接続していない） | 全社方針または事業部の目標・実行計画はあるが、両者が共通の目標と実行計画として接続されていない |
| 2（一部事業部に実行計画がある） | 一部の事業部には共通目標に基づく実行計画があるが、進捗確認や優先順位の調整は個別対応になっている |
| 3（共通計画で進捗を調整している） | 全社と事業部が共通の目標と実行計画で進捗を定期的に確認し、優先順位を調整した判断が記録されている |
| 4（双方向に計画を更新している） | 全社と事業部の実績や現場知を双方向に反映し、目標、実行計画、資源配分を継続的に更新している |

### 2. Staff (組織・人材)

#### サブテーマ: AI エヴァンジェリスト制度

**2.1** 全社のAI推進機能と各事業部の推進担当が役割を分担し、現場の課題と知見を双方向につなぐ仕組みがある。

| Score | 判定基準 |
|---|---|
| 0（推進機能が定まっていない） | 全社の推進機能も、事業部側の推進担当も定まっていない |
| 1（片側にだけ推進機能がある） | 全社または事業部の片側に推進する人や組織があるが、もう一方との役割分担や接続方法が定まっていない |
| 2（個別相談でつないでいる） | 全社の推進機能と一部事業部の推進担当が置かれているが、接続は個別相談に依存している |
| 3（主要事業部と双方向で運用している） | 双方の役割が文書化され、主要事業部との定例や相談経路が運用されている。課題解決または横展開の実績を少なくとも一つ確認できる |
| 4（全社の知見循環を改善している） | 全社の対象範囲で双方向の運用が定着し、現場から戻った知見によって全社方針・共通基盤・支援内容が継続的に更新されている |

**2.2** 事業部側のAI推進担当を、正式な役割として位置づけている。

| Score | 判定基準 |
|---|---|
| 0（推進担当が定まっていない） | 事業部側のAI推進担当の役割が定まっていない |
| 1（非公式に支援している） | AIに詳しい人が非公式に支援しているが、正式な役割にはなっていない |
| 2（一部事業部で正式な役割にしている） | 一部の事業部で、AI推進担当を正式な役割として位置づけている |
| 3（主要事業部で正式な役割にしている） | 主要な事業部で、AI推進担当を正式な役割として位置づけている |
| 4（AI推進担当を全社で正式化している） | AIによる変化の影響があるすべての事業部で、AI推進担当を正式な役割として位置づけ、役割に必要な時間・権限・評価上の扱いを定めている |

#### サブテーマ: AI 協働の可視化

**2.3** 従業員がAIエージェントを使う業務・利用度と、期待する価値とのつながりを可視化している。

| Score | 判定基準 |
|---|---|
| 0（利用実態を把握していない） | 従業員がAIエージェントをどの業務でどのように使っているかを、組織として把握できていない |
| 1（全体の利用量を把握している） | 利用者数、ログイン数、全体のトークン量は把握しているが、業務ごとの利用量や用途は分からない |
| 2（一部業務の利用量と用途を把握している） | 一部の業務または組織について、AIエージェントの利用量と用途を確認している。ただし、単発の聞き取りや担当者ごとの集計に依存するか、用途の分析が機能の分類にとどまり、同じ基準で継続比較できない |
| 3（主要業務の用途と価値を確認している） | 主要な業務について、定めた対象・頻度・記録方法で、AIエージェントの利用量と業務の場面に結びついた用途を継続的に把握し、期待する価値の仮説と対応づけて比較している |
| 4（対象業務全体の利用と価値を比較している） | 診断対象の組織の対象業務全体について、AIエージェントの利用量、用途、価値の変化を継続的に把握し、業務間・組織間・時系列で比較できる |

**2.4** AI協働の実態と従業員の声をもとに支援や業務の進め方を変え、その効果を継続的に確認している。

| Score | 判定基準 |
|---|---|
| 0（実態から改善していない） | AI協働を可視化しておらず、支援不足や価値の低い利用があっても改善されない |
| 1（一律の支援を行っている） | 全社一律の研修や利用促進を行っているが、利用量、使い方、価値、従業員の声に応じて内容を変えていない |
| 2（一部業務で改善している） | 一部の業務で可視化結果や相談内容を使って支援または業務を見直しているが、効果確認は個別対応に依存している |
| 3（人が主要業務の改善を回している） | 主要な業務で、人が利用量・使い方・価値と従業員の声を継続的に確認して改善対象を定めている。支援または業務を変更し、その効果を確認して、次の改善につなげている |
| 4（AIが継続的に改善を回している） | Score 3の状態を満たしたうえで、AIが利用実態と従業員の声から支援不足や価値の変化を継続的に検知し、改善案を示している。承認済みの範囲では支援の変更と効果確認まで行い、従業員への影響が大きい変更は人へ引き継いでいる |

#### サブテーマ: AI時代の学習とキャリア移行

**2.5** 従業員がAIによる仕事の変化に対応できるよう、学習と役割移行を支援する仕組みがある。

| Score | 判定基準 |
|---|---|
| 0（支援を用意していない） | AIによる仕事の変化に対応するための従業員支援を用意していない |
| 1（学習機会だけを用意している） | 任意の学習機会はあるが、役割の変化への対応には結びついていない |
| 2（一部職種を支援している） | 一部の職種で、学習・役割移行支援を実施している |

### 5. Security (AI ガバナンス)

#### サブテーマ: ポリシー連携と実行時統制

**5.1** 社員や業務のAIエージェントからのセキュリティの相談に、AIエージェントが自社の方針と判断基準にもとづいて答え、通常の相談は担当者の確認を待たずに完結している。

| Score | 判定基準 |
|---|---|
| 0（担当者が個別に答えている） | セキュリティ方針は人向けの文書にとどまり、相談にはセキュリティ担当者が個別に答えている。AIエージェントからは照会できない |
| 1（AIで方針を検索・要約している） | AIで方針の検索や要約を試しているが、答えは参考情報にとどまり、判断はセキュリティ担当者の確認を待っている |
| 2（一部で方針にもとづく回答を試している） | 一部の業務で、社員やAIエージェントの相談にAIが方針にもとづいて答えている。ただし、正式な判断として扱う範囲と根拠が定まらず、担当者の確認を省けていない |
| 3（通常の相談は担当者を待たずに判断している） | 主要な方針と判断基準を、対象・条件・結論に分けて、誰が聞いても同じ答えが返る形に整えている。社員とAIエージェントが同じ基準に照会して許可・条件付き許可・拒否を根拠とともに受け取り、通常の相談は担当者の確認を待たずに完結している。未定義、方針の衝突、例外は担当者へ引き継ぎ、自動で判断した相談の一部を担当者が定期的に抜き取って確かめている |
| 4（複数分野の通常の相談が人を介さず完結している） | セキュリティに加え、プライバシーや調達など複数分野の判断基準を横断して、基準に当てはまる通常の相談は人を介さず完結し、法的な解釈を要する相談は担当者へ引き継いでいる。相談と実行の結果から判断基準の改善案を作り、担当者が承認した変更を継続的に反映している |

**5.2** 業務のAIエージェントが行うリスクの高い操作を、そのAIエージェント自身が変更・回避できない仕組みで、実行前に制限・停止している。

| Score | 判定基準 |
|---|---|
| 0（AIエージェント未利用または統制なし） | 業務でAIエージェントを利用していない、またはAIエージェントの操作を実行前に制限・停止する仕組みがない |
| 1（記録や注意書きに頼っている） | 操作の監視・記録や、プロンプトの注意書き、AI自身の安全確認に頼っており、AIエージェントが変更・回避できない形では止められない |
| 2（一部業務で実行前に止めている） | 一部の業務で、リスクの高い操作を、AIエージェントが変更・回避できない仕組みで実行前に制限・停止している |
| 3（主要業務で実行前に止めている） | 主要な業務で、リスクの高い操作を、AIエージェントが変更・回避できない仕組みで実行前に制限・停止し、回避できないことを試験で確かめている |
| 4（全体に同じ統制を適用している） | 本番環境の対象全体で、AIエージェントが変更・回避できない仕組みがリスクの高い操作を制限・停止し、業務やAIエージェントを追加しても同じ統制が適用されている |

#### サブテーマ: 継続的な発見と診断

**5.3** 業務で使うAIエージェントとその接続先を導入前に評価し、稼働中も実環境から自動で集める仕組み（AIエージェントによる分析を含む）で継続的に把握して、未管理の利用や危険な変更を検知している。

| Score | 判定基準 |
|---|---|
| 0（AIエージェントを把握していない） | 業務で使うAIエージェントと接続先を、組織として把握していない |
| 1（申請記録で把握している） | 導入時の申請や表計算で把握しているが、導入前の評価の基準がなく、実環境との差も確認できない |
| 2（一部の環境で自動収集している） | 一部の環境から自動で情報を集めているが、導入前の評価、接続先や権限の把握、未管理利用や変更の検知に抜けがある |
| 3（導入前に評価し、稼働中も継続把握している） | 主要なAIエージェントについて、外部のモデル・ツール・サービスを導入前に評価している。稼働中もモデル、データ、ツール、権限、外部サービスを実環境から自動で継続把握し、未管理利用と危険な変更を検知して担当へつないでいる |
| 4（全社の接続からリスクを抑えている） | 全社のAIエージェントと接続先が実行状態から更新され、AIエージェントが変更の波及範囲とリスクを予測し、許可された範囲で未管理の接続の停止や権限の縮小を行って再確認している |

**5.4** 自社のセキュリティ状態をAIエージェントで継続的に診断し、攻撃経路や設定不備から、直す順番を示している。

| Score | 判定基準 |
|---|---|
| 0（AIで診断していない） | 自社のセキュリティ状態をAIで診断していない |
| 1（診断結果をAIで要約している） | 担当者が個別の脆弱性や診断結果をAIで要約している |
| 2（一部環境で診断を試している） | 一部の環境でAIエージェントによる診断を試している。ただし、個別の問題を攻撃経路や事業影響と結びつけられず、修正後の状態も確かめていない |
| 3（攻撃経路から直す順番を示している） | 主要な環境で、AIエージェントが脆弱性・設定・権限・ログを関連づけて分析している。攻撃経路と事業影響に基づいて直す順番を示し、修正の進み具合を追跡している |

#### サブテーマ: AIによる検証と自律改善

**5.5** 業務のAIエージェントへの攻撃や逸脱のシナリオをAIエージェントで作って実際に試し、防御を直して、同じ条件で効果を確かめている。

| Score | 判定基準 |
|---|---|
| 0（攻撃や逸脱を試していない） | 業務のAIエージェントへの攻撃や逸脱を試していない |
| 1（既知の攻撃を単発で試している） | 既知の攻撃例を担当者が単発で試し、見つかった問題を個別に直している |
| 2（一部で自動試験を始めている） | 一部のAIエージェントで、AIエージェントによるシナリオの作成や自動試験を行っている。ただし、本番相当の権限・接続が試験の条件に反映されず、直した後の再試験もできていない |
| 3（本番相当で試し、直して確かめている） | 主要なAIエージェントで、業務や構成の変化に合わせてAIエージェントがシナリオを作り、本番に近い条件で定期的かつ変更時に試している。見つかった弱点は承認のもとで直し、同じシナリオを繰り返し試して、攻撃の成功率が下がったことを確かめている |
| 4（脅威と変更から試験と改善を回している） | 外部の脅威情報、自社の事故・未遂、AIエージェントの変更をもとに、シナリオを更新し続けている。事前に承認した種類の防御の改善はAIエージェントが反映して再試験し、試験の結果を本番に出してよいかの判断に使っている |

**5.6** 自社のシステムへの攻撃をAIエージェントで実際に試し、見つかった弱点を承認された範囲で直して、同じ攻撃で塞がったことを確かめている。

| Score | 判定基準 |
|---|---|
| 0（攻撃を試していない） | 自社のシステムへの攻撃を実際に試していない |
| 1（単発の侵入テストで直している） | 外部の診断会社や担当者による侵入テストを年1回などの単発で行い、見つかった弱点を個別に直している |
| 2（一部でAIエージェントで試している） | 一部のシステムで、AIエージェントによる攻撃の試験や修正案の作成を行っている。ただし、試験、承認、反映、切り戻し、再試験が一つの流れになっていない |
| 3（試して直し、塞がったことを確かめている） | 主要なシステムで、事前に承認した範囲と安全策のもとで、AIエージェントが攻撃を定期的かつ変更時に試している。見つかった弱点の修正案を作り、承認と切り戻しの手順で反映し、同じ攻撃で塞がったことと、検知・対応が働いたことを確かめている |
| 4（限られた範囲を自律的に直している） | 5.4の診断や実際の異常からも試験を更新し続けている。事前に承認した種類の、自動で切り戻せる修正はAIエージェントが反映して再試験し、それ以外の変更は人が承認している。学びを他のシステムの防御へ展開している |

#### サブテーマ: 自動監査と適合性

**5.7** 業務のAIエージェントの判断と行動を、共通の実行IDで関連づけた証跡として継続的に残し、仕組み（AIエージェントによる分析を含む）で不足や矛盾を検知して、監査や事故調査に使っている。

| Score | 判定基準 |
|---|---|
| 0（監査証跡がない） | AIの判断と行動を監査や事故調査で追跡できる記録がない |
| 1（ログを手作業で集めている） | 個別システムにログはあるが、担当者が手作業で集めないと一件の実行をたどれない |
| 2（一部の証跡を関連づけている） | 一部の実行を関連づけているが、記録不足の検知、保存管理、実際の監査利用が定着していない |
| 3（主要な実行の証跡を残し、使っている） | 主要なAIエージェントの実行で、入力、参照情報、適用ルール、統制の判定、承認、操作結果を共通の実行IDで関連づけ、業務のAIエージェントや運用者が変更・削除できない形で保存している。不足と矛盾を検知し、監査または事故調査で実際に利用している |
| 4（全社証跡を継続監査している） | 業務部門やAIエージェントの運用担当が設定を変えられない、監査部門が管理する監査用のAIエージェントが、全社の証跡を継続的に評価し、記録の不足と統制の不備を見つけて是正の完了まで追跡している |

**5.8** 自社に適用される法規制・業界ルール・契約・社内ルールへの適合状況をAIエージェントで継続的に評価し、変更や不適合を検知して対応案を示している。

| Score | 判定基準 |
|---|---|
| 0（適合状況を把握していない） | 自社に適用される外部要求と社内ルールへの適合状況を、整理して把握していない |
| 1（文書・表計算で管理している） | 担当者が文書と表計算で要求を管理し、変更時に手作業で確認している |
| 2（AIで要求の検索・要約をしている） | AIが要求の検索や要約を支援しているが、実際の統制と証跡の継続比較や対応追跡はできていない |
| 3（統制・証跡と継続比較している） | 主要な外部要求と社内ルールを、AIエージェントが実際の統制・証跡と継続的に比べ、変更と不適合を検知して影響範囲、対応案、担当を示している。適合の証拠には元のシステムの記録を残し、AIエージェントの評価と区別している |
| 4（要求を統合し更新を再確認している） | 複数の要求を重複なく統合し、変更の影響分析からポリシー、検証、監査の更新案を作り、承認後の反映と適合性を再確認している |

#### サブテーマ: AIによる事故対応と復旧

**5.9** 業務のAIエージェントへの攻撃や制御不能の兆候を、稼働中の行動の量や組み合わせから監視の仕組み（AIエージェントによる分析を含む）で検知し、権限の制限や安全な停止を自動で行って、影響を封じ込めている。

| Score | 判定基準 |
|---|---|
| 0（検知・封じ込めできない） | AIエージェントへの攻撃や制御不能を、人が問題を認識するまで検知・封じ込めできない |
| 1（異常を通知している） | 監視の仕組みが異常を通知するが、影響範囲の推定や封じ込めは人が個別に行っている |
| 2（一部異常に自動対応している） | 一部の異常に自動対応しているが、権限、停止範囲、人への引継ぎ、業務影響が整理されていない |
| 3（主要なAIエージェントを自動で封じ込めている） | 主要な本番のAIエージェントについて、業務のAIエージェントが止められない監視の仕組みが、しきい値とAIエージェントによる分析で攻撃や制御不能の兆候を検知し、影響範囲を推定して、許可された権限の制限・接続の遮断・安全な停止を実行し、重大な判断を人へ引き継いでいる |
| 4（全社で連携して封じ込め・改善している） | 本番の対象全体で、業務AIからは止められない監視と封じ込めの仕組みが連携し、攻撃や制御不能の影響を封じ込めて代替運用へ切り替えている。演習と実事故の結果を、検知条件、権限、引継ぎへ反映している |

**5.10** 自社のセキュリティ事故に、AIエージェントで検知と調査から、封じ込め、復旧、報告までを進め、是正後の安全性を再検証している。

| Score | 判定基準 |
|---|---|
| 0（事故対応の流れが定まっていない） | セキュリティ事故の検知、調査、封じ込め、復旧、報告、再発防止の流れが定まっていない |
| 1（人が個別に対応している） | 担当者が個別に対応し、AIは記録の要約や報告書の下書きに使われる程度 |
| 2（AIエージェントが一部を支援している） | 一部の事故で、AIエージェントがアラートの一次判定や原因の調査を支援している。ただし、封じ込め、データ整合性の確認、復旧、報告、再検証が一連の対応として運用されていない |
| 3（検知から再検証までを進めている） | 主要なシステムの事故で、AIエージェントがアラートの一次判定と、証跡からの原因と影響の調査を行い、事前に決めた範囲の封じ込めを実行し、それ以外は人の承認を得ている。データ整合性を確認して復旧し、期限に沿った報告を支援し、是正後は再開前に安全性を再検証している |
| 4（事故から防御と復旧を更新している） | 事故と演習から得た学びをもとに、AIエージェントがポリシー、検知条件、試験のシナリオ、復旧手順の更新案を作っている。反映後の再発リスクと、対策後も残るリスクを継続的に確認し、経営へ示している |

## 4. ガイド「AXISと読む AX Criteria」本文（原文、HTML装飾を除去）

> 以下は `/api/guide` の本文。見出し階層は原文のまま一段下げて転記する。

### AXISと読む AX Criteria

> こんにちは、AXISです。
> この10枚で、AX Criteriaが目指すことと、診断の考え方をご案内します。

#### AI エージェントとの協働を、日本企業の当たり前に。

**2030 年、日本企業のどこにも AI を使いこなす経営と現場がある。**

その未来に向けて、自分たちの現在地と、次の一歩を考えるための物差しです。

AX Criteriaの正式名称はAgentic Transformation Criteriaです。企業のAIエージェント変革を対象とする、日本CTO協会の自己診断フレームワークです。

Mission・VisionはAX Criteriaの設計上の確定事項に基づいています。2030年の記述は目指す未来であり、達成の予測や保証ではありません。

### AXって何？

> インターネットが情報の移動と共有を変えたように、AIは「誰が仕事を実行するか」を変えます。そこから、働き方や組織も見直していきます。

#### AIエージェントとの協働を前提に、仕事と組織を変える

考え、試し、作る費用が下がることで、仕事の前提が変わります。

- **人の役割が変わる**：目的を決め、AIに任せ、結果を評価し、責任を持つ。
- **学び方が変わる**：判断を経験し、熟練者の知恵を次の仕事で再利用する。
- **組織の動かし方が変わる**：業務全体を組み直し、生まれた余力を新しい価値へ向ける。

AXはAgentic Transformationの略です。AIエージェントとの協働を前提に、個人の仕事の進め方から、人材育成、業務の流れ、組織の役割まで見直していく変革を指します。

#### ここでいうAIエージェント

複数の業務ツールと接続し、組織・業務固有の情報や判断基準を扱いながら仕事を実行するAIツールです。対話だけで完結するAI機能とは区別します。

たとえば、問い合わせを受け取り、顧客情報と社内手順を確かめ、許可された対応を進め、判断に迷う場合は人へ引き継ぎます。製品名で判定せず、実際に任せている業務、利用する範囲、継続して運用する仕組みを確かめます。この例は導入必須の業務ではありません。

#### 変化をどう捉えるか

人の仕事には、目的や制約を伝えること、仕事を分けて任せること、成果を評価することが増えていきます。職種をまたいで担えるタスクも広がり、人が常に操作していない時間にも実行を進められます。AIに作業を委任しても、目的・権限・評価基準を決め、結果に責任を持つ役割は人に残ります。

育成では、AIの下書きを本人が評価・修正し、判断理由を説明して、現場で結果を確かめる経験が大切になります。熟練者の判断基準や良い例・悪い例も、次の仕事で参照し、検証し、再利用できる形にします。試作品を使い、結果から要件を見直す学び方も取り入れられます。

個人の作業が速くなっても、承認待ちや確認待ちが残れば、顧客に届く価値は増えません。人とAIの分担や業務全体を見直し、生まれた余力を新しい価値、学習、働き方の改善へどう配るかを考えます。

効果は仕事の性質や評価方法によって異なります。生成や実行の量が増えるだけで成果が高まるとは限らず、実際に使って、検証や確認の負担も含めて確かめます。

### 使って理解し、経験を組織の力へ

> 自分で使ってみると、任せたい仕事や、大切にしている判断が見えてきます。その経験を持ち寄ることが、組織の変化につながります。

#### 使って理解する

経営も現場も、自分の仕事でAIを使い、その経験から判断や業務の進め方を見直します。

#### 暗黙知をエネルギーに

現場の経験や判断のこつを言葉にして、AIとの協働や組織の学習につなげます。

「使って理解する」「暗黙知をエネルギーに」は、AX Criteriaが大切にする価値観です。個人が得た経験や気づきを持ち寄り、組織として仕事や判断を見直す力へつなげます。

DX Criteriaは、社会の変化への適応力を支える具体的な習慣を言語化し、高速な仮説検証能力を育てる考え方を示しています。AX Criteriaはその系譜を踏まえ、AIエージェントと協働する企業の能力に焦点を当てています。

AX Criteriaは5Sを持つ独立したフレームワークです。DX Criteriaの「2つのDX」を「2つのAX」へ置き換える設計ではありません。

[DX Criteria「策定の目的とビジョン」](https://dxcriteria.cto-a.org/660d6573b45645bcb431c7c29c5431f8)（2025年4月更新、2026年9月確認）

### 組織を見る、5つの視点

> 技術だけでなく、経営、人、仕事の分担、ガバナンスも見ます。5つを一緒に見ることで、つながりが分かります。

| 5S | 確かめること |
| --- | --- |
| Strategy | どこで価値を生み、何に資源を配るか |
| Staff | 人が学び、役割を変えられるか |
| System | AIを安全に、継続して動かせるか |
| Symbiosis | 人とAIで、仕事をどう分担するか |
| Security | AIの出力と行動を統制できるか |

**5つのカテゴリから、組織の現在地を確かめます。**

各カテゴリは5サブテーマ×2項目で10項目です。5Sの順序はStrategy、Staff、System、Symbiosis、Securityで固定しています。

カテゴリの正式な日本語表記は、経営戦略・価値再配置／組織・人材・AIエヴァンジェリスト／AIを動かす技術基盤／人とAIの業務分担／AIガバナンスです。

SystemはAIを動かす技術基盤、Symbiosisは実際の業務での分担を扱います。基盤の整備と、仕事を任せている範囲を分けて確かめます。

### カテゴリから、50の問いへ

> 大きな視点から、具体的な問いへ。一つのカテゴリに5つのサブテーマ、その一つひとつに2つのクライテリアがあります。

| 階層 | 全体の数 | 内訳 |
| --- | --- | --- |
| カテゴリ | 5 | 組織を見る、大きな視点 |
| サブテーマ | 25 | 1カテゴリに、5つの論点 |
| クライテリア | 50 | 1サブテーマに、2つの問い |

#### たとえば、Systemの中を見ると

**System → エージェント利用・自動化基盤 → 3.1・3.2**

評価するのは、一つひとつのクライテリア。各項目を0〜4で確かめます。

クライテリアは、組織にどのような仕組みがあるかを問う診断項目です。5カテゴリ×5サブテーマ×2項目で、全体は25サブテーマ・50項目になります。

Systemの「エージェント利用・自動化基盤」には、組織としてAIエージェント環境を管理する3.1と、タイマーや業務イベントで起動して継続実行する基盤を問う3.2があります。

[3.1の項目と解説](https://axcriteria.cto-a.org/assess?item=3.1&panel=explanation) ／ [3.2の項目と解説](https://axcriteria.cto-a.org/assess?item=3.2&panel=explanation)

### 絶対的な基準ではありません

> この物差しで、会社のすべてが分かるわけではありません。結果を見ながら、何が見えていて、何を見落としていそうかも話してみましょう。

#### いまの知見を整理した、共通の目安です

AX Criteriaは、AIエージェントとの協働に必要な仕組みを、実践と議論から整理しています。

技術や事業環境が変われば、問うべきことも変わります。**自社の状況や、基準が捉えきれていないこと**も、合わせて考えます。

共通の評価基準に沿って現在地を確かめることと、自社の文脈で結果を解釈することを分けて考えます。採点には項目ごとの0〜4の評価基準を使い、対象範囲と判断の根拠をそろえます。

全社と事業部、回答した時期、回答者が把握している事実によっても結果の読み方は変わります。判断できないことは保留し、誰に何を確かめるかを整理します。

基準が自社の実践を十分に捉えていないと感じた場合、その具体的な場面も、基準を見直すためのフィードバックになります。

### 次の一歩は、自分たちで決める

> 同じ点数でも、次に取り組むことは組織によって違います。自分たちが実現したいことと、照らし合わせてみてください。

#### 点数から、何に取り組むかを話す

点数だけで、企業や人の優劣は決まりません。事業の目的や組織の状況に照らして、取り組む順番を考えます。

満点を一律の目標にせず、**経営と現場が、自分たちの言葉で次の一歩を選びます。**

同じ項目を満たす方法にも、さまざまな形があります。特定の製品や組織体制を正解にせず、実際にどのような仕組みが働いているかを確かめます。

診断は、自社の経営層・推進担当者・現場が一緒に考えるために使います。コンサルタントや顧問は、その判断を支える伴走者として関わることができます。

点数を部署のランキングや人事評価へ直結させると、正直な対話を損ないます。回答が異なる場合は、その背景にある仕事や判断、見えている事実の違いを確かめます。

### みんなの実践で、基準も進化する

> 使って気づいたことも、ぜひ教えてください。うまくいった実践も、当てはまらなかった場面も、この物差しを育てる手がかりになります。

#### 公開・共同・継続更新

「この問いは分かりにくい」「こんな実践もある」。現場の声を集め、議論し、項目や解説を更新していきます。

**企業が診断から学び、その経験からAX Criteriaも学ぶ。**

使う人も、基準を育てる一員です。

「公開・共同・継続更新」は、AX Criteriaが大切にする価値観です。専門家と現場の実践者が知見を持ち寄り、技術や組織の変化に合わせて基準を育てます。

寄せられた声は、具体的な場面や判断の根拠を確かめ、ほかの実践とも照らし合わせて、改訂の材料にします。一つの意見をそのまますべての企業へ当てはめず、議論を通じて項目や解説を見直します。

AX CriteriaはCC BY-SA 4.0のもとで公開・共同・継続更新するフレームワークです。

### 0〜4で、仕組みの現在地を確かめる

> 迷ったら、その項目の評価の目安を開いてください。実際の仕事で起きていることを手がかりに、一段ずつ確かめます。

| Score | 共通の考え方 |
| --- | --- |
| 0 | 取り組みがない |
| 1 | 必要性を認識し、議論や個人的な試行を始めている |
| 2 | 一部の部門・業務で試験的に取り組んでいる |
| 3 | 主要な範囲で、仕組みとして導入・運用している |
| 4 | 制度・文化として定着し、記録と改善を続けている |

実際の判定には、項目ごとの0〜4の評価基準を使います。

この表は本番APIの共通尺度を要約しています。項目固有のScore Guideがある場合はそちらを使います。Score 4でAIによる自律化を問う項目もあり、すべてを単に「定着しているか」だけで判定しません。

分からない場合は根拠のない点数を付けず、保留して確認する相手や事実を整理できます。低い点数を失敗と決めつけず、どこへ支援や改善の取り組みを向けるかを考えます。

#### 結果を、次の対話へ

全社か事業部か、対象を決めて診断します。経営と現場で結果を持ち寄り、認識の違いを確かめます。

**どこを変えるか、誰と取り組むか。** 自社の言葉で、次の一歩を決めます。

全社と事業部の診断を比べるときは、それぞれが対象とした範囲を明示します。範囲の違う点数を、そのまま優劣として扱いません。

診断をコンサルタントへ丸投げせず、自社の経営・推進担当・現場が判断を担います。コンサルタントや顧問は伴走者として関わることができます。点数を上げること自体を目的にしたり、部署のランキングや人事評価へ直結させたりすると、正直な対話を損ないます。

AX CriteriaはCC BY-SA 4.0のもとで公開・共同・継続更新するフレームワークです。使って分かったことを持ち寄り、物差しも一緒に育てていきます。

グラフは説明用の架空の数値で、実在する企業の診断結果や推奨値ではありません。実際の結果画面では、保留回答がある場合にスコアの変動範囲も表示します。


## 5. 発表情報（PR TIMES、2026年10月5日）

- 発行主体: 一般社団法人日本CTO協会。2026年7月1日に「AX Criteria WG」の設置を発表（DX Criteriaを継承し、組織のAI成熟度をはかる新指標を策定）。2026年10月5日（デジタルの日）に公開。
