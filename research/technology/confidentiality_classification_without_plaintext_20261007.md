# 平文を分類側へ開示せず、機密性を判定する方法

2026年10月7日。対象は企業内に限定せず、研究機関・銀行・政府等も含む。利用者の関心はAIの学習ではなく、**内容を分類するAI・サービスへ平文を渡さず、「機密かどうか」を判定すること**である。前の[広い事例調査](enterprise_sensitive_data_ai_cases_20261007.md)を、この目的で読み替える補足調査。

## 要求の整理

「分類サービスに内容を見せず判定する」は、準同型暗号やMPCによる秘匿した分類で可能。ただし「情報をまったく利用せず、内容由来の機密性を判断する」ことはできない。暗号化した計算は内容に対応する数値を使うが、計算主体へその平文を開示しない。

通常の暗号化ファイルを復号鍵なしでそのまま一般的なAIに渡して、意味を読み取らせる方式ではない。暗号化の前に、対応する分類処理へ入力を変換し、専用の暗号方式・計算手順を用意する。ファイル形式を解析し文字を取り出す段階と、分類する段階も分けて確認する必要がある。

また機密性は内容だけで決まらない。同じ文章でも、未公表の研究結果か、すでに公開された情報か、秘密保持契約の対象かで扱いが変わる。分類モデルの出力と、組織の規則による最終区分は区別する。以下の研究は主に「内容を隠した文章分類」の証拠であり、機密区分の正しさを保証する証拠ではない。

## 目的に近い研究

| 研究 | 平文を開示しない範囲 | 今回の目的への適合と限界 |
|---|---|---|
| **PrivFT: Private and Fast Text Classification with Homomorphic Encryption**（2019年公開、IEEE Access 2020） | 所有者が文章の入力表現を暗号化し、サーバーが復号せず分類。結果も暗号化して返す | 暗号化した文章入力の分類を実装。機密／非機密の学習済み分類器へ応用する候補だが、原論文の実験をそのまま機密判定の精度と扱わない |
| **Privacy-Preserving Classification of Personal Text Messages with Secure Multi-Party Computation: An Application to Hate-Speech Detection**（2019年初稿、取得した版は2021年改訂） | 秘密計算で特徴抽出と分類を行う。分類サービスは文章を知らずに結果を得る | **平文を読む特徴抽出AIも避けたい場合に特に近い**。原実験は差別的発言の検出であり、機密性判定ではない |
| **Privacy-Preserving Text Classification on BERT Embeddings with Homomorphic Encryption**（NAACL 2022、arXiv掲載は同年10月） | 所有者側で作った文章の数値表現を暗号化し、サーバーが分類 | 分類側に元文・平文の数値表現を渡さない。ただし**所有者側のBERTは平文を読む**ため、「どのAIにも平文を読ませない」という要求には適合しない |

原本： [PrivFT](https://arxiv.org/abs/1908.06972)、[秘密計算での文章分類](https://arxiv.org/abs/1906.02325)、[BERTの数値表現による暗号化分類](https://arxiv.org/abs/2210.02574)。PDF3件・36頁と抽出本文を保存済み。取得記録は[出典台帳](enterprise_sensitive_ai_sources_20261007.json)の `privft`、`mpc_text_classification`、`bert_encrypted_classification`。

### PrivFTで読む箇所

PDF1～3頁に目的・入力所有者と分類側の役割、4頁以降に暗号方式と分類器の構成。所有者が入力を暗号化し、平文の学習済みモデルを持つサーバーで評価、暗号化された分類結果だけを所有者へ返す。準同型暗号とは、暗号文を復号せず演算して、復号後に対応する結果を得る暗号方式。暗号化したモデルの学習も扱うが、今回の検討では推論部分を使う。

### 秘密計算による文章分類で読む箇所

PDF1～5頁に利用者と分類側の構成、秘密のままの特徴抽出、ロジスティック回帰・木を組み合わせる分類器。6頁以降に安全性と実験の説明がある。MPC（Multi-Party Computation）は複数の主体が秘密を分けて持ち、内容を相互に明かさず計算する方法。この論文では、文章だけでなく相手の分類モデルも保護対象に含める。

所有者による入力の準備までゼロになるわけではないが、BERTのような平文を読む言語モデルを先に動かす必要がある方式とは異なる。必要な脅威の想定、計算主体の結託、結果の受領者を、導入時に別途確認する。

### BERTによる暗号化分類で読む箇所

PDF2頁の図1が重要。利用者が文章の数値表現を生成し、暗号化、分類側が暗号文を処理する順序が分かる。PDF4～5頁には評価と限界がある。暗号化する前の数値表現は文章の情報を含み、元文の推定につながり得るため、**数値へ変換しただけで匿名化したとは扱わない**。

## 既知の機密データとの照合という別の方法

Virginia Tech・Purdueの研究 **Privacy-Preserving Detection of Sensitive Data Exposure**（IEEE TIFS 2015）は、登録済みの機密データから照合用の特徴を作り、元データを検出業者に見せず漏えいを検出する方向を扱う。著者の博士論文の[第5章](https://vtechworks.lib.vt.edu/bitstream/handle/10919/71463/Shu_X_D_2016.pdf)に構成と評価がある。

これは「この文章に既知の機密データの一部が含まれるか」を調べる方式であり、未知の文章の意味から「これは営業秘密か」を決める方式ではない。検出側に照合対象の通信がどのように見えるかも別条件であり、**すべての入力が暗号化されたままという保証に拡張してはいけない**。研究は限定された情報の漏れを扱い、規則に従いつつ情報を探ろうとする検出側を想定する。漏えいが完全にゼロという説明はしない。

この系統は「漏えいさせたくない情報がすでに決まっている」場面に近い。未登録の個人情報、言い換え、新しい秘密、文脈依存の機密性には別の検出が必要。

## 名前は近いが今回の条件を満たさない例

- **TEE内で機密分類する**：管理者・外部提供者に見せない保護にはなるが、保護領域内の分類AIは平文を読む。
- **個人情報をAIで検出してから削除する**：検出AIには削除前の内容が必要。削除後に別のAIへ渡す構成は、最初の分類を秘匿したことにはならない。
- **暗号化された文書を通常のDLPで検査する**：DLPは機密情報の持出し等を検出・制限する仕組み。復号権限を持つサービスが読む場合は、暗号化したままの演算とは違う。Microsoftの[SharePoint／OneDriveの説明](https://learn.microsoft.com/en-us/purview/sensitivity-labels-sharepoint-onedrive-files)も、保護文書を復号して処理する動作を含む。
- **2026年7月の機微情報判定を含む研究**：[A Privacy-Preserving Middleware Architecture for Detecting Prompt Injection and Sensitive Data Exposure in Large Language Model Interactions](https://www.preprints.org/manuscript/202607.1897)は、送信前にローカルの小型言語モデル等で判定する構成。目的は近いが、モデルは平文を読む。査読前の公開原稿であり、本番導入の証拠ではない。

## 判定方式の選び方

| 判定したいこと | 候補 | 内容を使わずに判定できるか |
|---|---|---|
| 作成部署、保存先、既存の区分、契約、公開状態から機密区分を決める | 既存の属性と規則による分類 | 本文を読まずに可能。ただし属性が正確で十分な場合に限る |
| 登録済みの秘密・口座情報等が含まれるか | 秘匿した照合 | 元の秘密を検出側へ開示せず可能。未知の秘密の意味判断とは異なる |
| 内容を基に機密／非機密を予測する | MPC／準同型暗号による専用分類器 | 内容に由来する情報を秘匿して計算する。分類側には平文を開示しない |
| 長い文書の意味・契約関係まで解釈して理由を説明する | 秘密計算に対応する高度なモデル、または保護領域での推論 | 前者は計算・実装制約が大きい。後者はAIが平文を読む |

今回最も直接的な検証対象は、**「機密」「非機密」「要確認」という固定した出力を返す、秘密計算による文章分類器**である。これは本調査の設計提案であり、上記組織の機密判定への本番導入実績ではない。

最初に、対象が未分類の任意の文章なのか、登録済み情報との照合なのかを決める。次に、誰から平文を隠すか、入力準備をどこで行うか、結果を誰が知るかを定義する。分類結果自体が「この人は特定の病気に関係する」などの秘密を明かす場合もあるため、結果にも開示範囲を設ける。精度は実際の機密区分で評価し、見逃し率、誤判定、未経験の分野、繰返し照会による推定を確認する。

**公開資料で確認できたのは、秘匿した分類の研究実装と、既知の機密データの検出研究である。銀行・政府等が、任意の文書の機密区分を平文非開示で本番判定している具体的事例までは確認できていない。** 一般的な文章分類の実験を機密判定の導入事例と取り違えない。

追加調査：[ゼロ知識証明と関連技術](zero_knowledge_sensitive_data_research_20261007.md)は、原本を渡さず条件・計算を検証する方式と、分類AIから平文を隠す方式の関係を整理する。[医療データとLLMの管理](medical_data_llm_controls_20261007.md)は、施設内モデルと管理された外部接続の具体例を比較する。

## LLMを使わない分類と施設内LLMの精度比較

LLMは必須ではない。規則による番号・語の検出、既存属性による区分、単語の出現傾向と統計的な分類器、BERT等の文章理解用モデルでも分類できる。ここでBERTは、自由な文章生成を主目的とするLLMと区別して説明する。施設内で動かすという設置方式自体は、精度が高い根拠にならない。重要なのは対象言語・文書、学習資料、分類規則、モデル・設定である。

**Benchmarking Classical and Transformer-Based Models for Document Sensitivity Classification**（2026年、査読前）は、外交文書16,000件の機密性分類で6方式を比較。本文中に残る機密区分の表示を除去し、BERTが比較対象内で最高の正解率89.14%、F1 89.33%を報告する。従来型では、単語の出現傾向を重み付けするTF-IDFとロジスティック回帰が低い計算負荷で有力だった。[論文](https://arxiv.org/abs/2608.16928)。この実験は生成LLMとの直接比較ではない。PDF6頁を保存し、比較条件・結果を確認した。本文の既存区分を当てるだけの評価と、内容からの分類を区別する点が重要。

**Protecting medical privacy with pretrained language models: named entity recognition-based de-identification in Korean unstructured electronic medical records**（npj Health Systems、2025年）は、医療記録内の識別情報を検出する学習済みKLUE BERTと、質問・少数例で指示した公開LLMを比較し、BERTの優位を報告する。[論文](https://www.nature.com/articles/s44401-025-00036-1)。これは韓国語の識別情報検出であり、任意の企業文書の機密区分を分類する実験ではない。学習条件の違いもあるため、全BERTが全LLMに勝つとは説明しない。PDF11頁を医療資料台帳に追加した。

一方、**Security Document Classification with a Fine-Tuned Local Large Language Model: Benchmark Data and an Open-Source System**（2026年、査読前）は、TorchSightのQwen 3.5 27Bを分類用途に追加学習し、1,000文書で区分の正解率95.0%、比較した商用モデルは同じ質問条件で75.4～79.9%と報告する。[論文](https://arxiv.org/abs/2605.20368)。PDF22頁を保存した。追加学習済みモデルと質問のみの比較であり、「施設内だから優れる」ことや従来型分類器全体への優位の証明ではない。上記外交文書研究とは資料・区分が違うため、95.0%と89.14%を順位付けに使わない。

選定では同じ正解付き文書を使い、規則、従来型分類器、BERT系、施設内LLMを比較する。機密の見逃し率、非機密を止める率、判断保留を含めた自動処理の割合、処理時間・費用を測る。正解率だけでなく、見逃しを許容範囲内にした場合の処理能力を比べる。類似文書や同じ書式が学習側と評価側へ分かれて混入することも避ける。

以上からの設計案は、明確な規則・既存属性で判定し、専用分類器で残りを処理し、判断が割れる文脈依存の資料を施設内LLMまたは人へ送る構成。ただし、どの段階で平文を読むかは別に決める。LLMを使わないだけでは、平文を読まない構成にはならない。
