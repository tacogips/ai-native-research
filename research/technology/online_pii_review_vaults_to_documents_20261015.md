# 独立レビュー：オンライン文書閲覧・保存制限

確認日：2026-10-15。対象：[文書閲覧稿](online_pii_document_access_20261015.md)、[資料台帳](online_pii_document_sources_20261015.json)。保存した公開原本の本文と採用主張を照合した。契約画面、端末残存、通信経路、回避操作、実利用者への配布は試験していない。

## 判定と重要境界

重大な訂正はない。「原本ファイルの保存禁止」「表示データの受信」「永続保存」「画面複製」を分けており、オンライン閲覧やメール確認を原文が端末へ届かない保証にしていない。

| 確認対象 | 原本支持・判定 |
|---|---|
| Box Previewer | `box_roles.txt` L384は管理設定によりモバイルのオフライン保存が可能、L395は権限重複時に緩い方を優先と記載。Previewer設定一つで端末非保持としない説明は妥当。ViewerとPreviewerの区別、単一ファイル招待の役割制約も支持あり。 |
| SharePoint BlockDownloadPolicy | `ms_block.txt`はブラウザー限定と保存・印刷・同期の制限、サイト所有者・指定グループの除外、app-onlyで実行するサービスアプリの例外を記載。サイト方針を全API取得の遮断としない説明は妥当。本文上部に認証案内はあるが、仕様本文そのものは公開取得できており「ログイン画面のみ」と誤判定しない。 |
| DocSendのメール確認 | `docsend_auth.txt`は検証リンク最大1時間・同一端末、検証済み状態2週間を記載。毎回のOTPと区別している。`docsend_downloadonly.txt`の形式例外も別に扱っている。 |
| Digify Screen Shield | `digify_shield.txt`は表示領域縮小・非表示/ぼかしに加え、画面の連続撮影やOS/ブラウザーの阻止不能操作を明記。完全防止としておらず妥当。`digify_send.txt`のStricter email verificationはアクセスごとの本人確認を説明する。 |
| FINAL CODE | `finalcode_blog.txt` L56は暗号化したBrowser Viewファイルのメール添付事例。`finalcode_manual.txt` L15はプリンター制御の制限、L19は100MB、L21–27は非対応形式と旧版の条件を説明する。ブラウザー利用とファイル無配布を同一視しない記述は支持あり。 |

## 補足要求 D-R1（軽微）：NISTのメール確認コード例外

`nist_auth.txt` L303–307はメールを帯域外の認証に使わないとする一方、メールアドレスの検証用コードや回復コードは同規定の認証過程とは異なり、その禁止の対象ではないと明記する。現稿はすべての商用メール確認を違法・無意味とはしないと述べているため誤断定ではないが、DocSend等の所有確認とNIST準拠の認証を一層明確に分けるため、この明示的な例外を一文追記するよう依頼した。[NIST原本](https://pages.nist.gov/800-63-4/sp800-63b.html)

## 取得整合と確認範囲

台帳25項目のうち保存できた原本・派生テキストの全記録ハッシュを再計算し、不一致なし。未展開gzipや500バイト未満の抽出本文は検出しなかった。失敗したBox APIページは根拠に使っていない。これは取得物の整合確認であり、商用製品の全通信・実保存状態や表示用SDKの固定版実装を監査した意味ではない。

補足後の確認は末尾へ追記する。
