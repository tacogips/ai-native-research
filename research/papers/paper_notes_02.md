# arXiv 論文解説 2：検索・知識構造・実行基盤

取得した PDF の冒頭と本文の該当節に基づく。数値の業務への外挿と、実験の再現は行っていない。各 PDF はローカル取得済みファイルへのリンク。

## 2310.06816：検索用ベクトルから元の文章を復元する

原題：Text Embeddings Reveal (Almost) As Much As Text。[原文](https://arxiv.org/abs/2310.06816)、[PDF](arxiv/2310.06816/paper.pdf)。確認：1頁、9頁。

- **概要：** 文章を数値化した埋め込みから、元の文章を生成し直す攻撃を調べる。
- **重要点：** 生成、再数値化、差分の修正を繰り返し、指定された32単位の短文では高い完全復元率を報告する。
- **限界：** 評価対象のモデル・文章長・攻撃条件に依存する。全てのベクトルの復元率ではなく、防御へ適応する攻撃にも残課題がある。
- **示唆：** 埋め込みを非機密と扱わず、原文と同様に権限・削除・持ち出しを管理する。

## 2310.08560：長い対話のための階層的な記憶

原題：MemGPT: Towards LLMs as Operating Systems。[原文](https://arxiv.org/abs/2310.08560)、[PDF](arxiv/2310.08560/paper.pdf)。確認：1頁、3頁。

- **概要：** モデルが一度に読める量の制限を、作業用の記憶と外部保存の間の情報移動で補う。
- **重要点：** 読み取り専用の指示、編集可能な作業領域、過去の会話、長期保存を分け、呼び出しを通じて必要な情報を移す。
- **限界：** 記憶の長さを補うことと、記録の真実性・正式な状態・認可を保証することは別。
- **示唆：** 業務の正本を外部のデータベースへ置き、判断に使った記憶の識別子と版を残す。

## 2311.07509：企業の質問に対する関係データと SQL の比較

原題：A Benchmark to Understand the Role of Knowledge Graphs on Large Language Model's Accuracy for Question Answering on Enterprise SQL Databases。[原文](https://arxiv.org/abs/2311.07509)、[PDF](arxiv/2311.07509/paper.pdf)。確認：1頁、14頁。

- **概要：** 保険分野の企業データを使い、直接 SQL を生成する方式と、意味を定義した知識グラフ経由の方式を比較する。
- **重要点：** 存在しない列や誤った結合に加え、グラフでも誤った経路が生まれることを分析する。業務の意味を渡す層が性能に影響する。
- **限界：** 提供企業による特定の問題・形式での比較。一般にグラフが SQL より優れるという証明ではない。
- **示唆：** 技術の名前だけで選ばず、自社の質問、意味定義、正しい結合・経路を固定して比較する。

## 2402.07456：操作手順を蓄積する汎用計算機操作支援

原題：OS-Copilot: Towards Generalist Computer Agents with Self-Improvement。[原文](https://arxiv.org/abs/2402.07456)、[PDF](arxiv/2402.07456/paper.pdf)。確認：1頁と構成・評価節。

- **概要：** 特定アプリだけでなく、計算機の複数の機能を扱う実行基盤と、手順を学んで蓄積する FRIDAY を示す。
- **重要点：** 計画、実行、手順の保存・改善を組み合わせ、実際のアプリを使う課題を評価する。
- **限界：** 手順を再利用できることは、その手順が安全・最新版・業務上適切である保証ではない。
- **示唆：** 新しい手順は候補として隔離し、評価と承認を経た版だけを本番へ昇格させる。

## 2402.11163：知識グラフ上の複雑な質問を道具で解く

原題：KG-Agent: An Efficient Autonomous Agent Framework for Complex Reasoning over Knowledge Graph。[原文](https://arxiv.org/abs/2402.11163)、[PDF](arxiv/2402.11163/paper.pdf)。確認：1頁と限界節。

- **概要：** 知識グラフへの質問を、必要な操作を選んで実行する仕組みにより解く。
- **重要点：** グラフの操作道具、作業状態、学習した指示追従を組み合わせ、複数段の関係を扱う。
- **限界：** 基盤モデルと学習条件への依存があり、他モデルでの比較が残る。会社の不完全・更新中の知識で同じ成績になるとは限らない。
- **示唆：** 読み取り操作を型と権限で制限し、経路の根拠と有効期間を検査する。

## 2403.02691：外部文書に埋め込まれた不正指示の評価

原題：InjecAgent: Benchmarking Indirect Prompt Injections in Tool-Integrated Large Language Model Agents。[原文](https://arxiv.org/abs/2403.02691)、[PDF](arxiv/2403.02691/paper.pdf)。確認：1頁、10頁。

- **概要：** メールや検索結果などの外部情報に攻撃者の指示を入れ、ツールを使う AI が不正操作へ誘導されるかを評価する。
- **重要点：** 情報窃取や利用者への損害を対象に、通常の指示と外部内容の境界を検証する。
- **限界：** 攻撃文や評価設定が変わると結果も変わる。当該問題集の成績を全攻撃への耐性と解釈できない。
- **示唆：** 外部文書を閲覧可能であることと、そこに書かれた操作指示が正当であることを分ける。

## 2403.04960：AI アプリ同士の実行を隔離する

原題：IsolateGPT: An Execution Isolation Architecture for LLM-Based Agentic Systems。[原文](https://arxiv.org/abs/2403.04960)、[PDF](arxiv/2403.04960/paper.pdf)。確認：1〜3頁。

- **概要：** 第三者の AI アプリが共有の情報や機能へ自由に接続する危険を、実行領域と通信の分離で抑える。
- **重要点：** アプリ間の連携を仲介し、不正なアプリが他の情報・操作権限へ影響する経路を制限する。
- **限界：** 自然言語でのやり取りや許可された通信の意味は、従来の処理境界より曖昧になり得る。
- **示唆：** 共通の巨大な会話へ全アプリの情報を入れず、必要な情報と操作だけを受け渡す。

## 2403.16971：AI 実行の資源管理を共通層へ集める

原題：AIOS: LLM Agent Operating System。[原文](https://arxiv.org/abs/2403.16971)、[PDF](arxiv/2403.16971/paper.pdf)。確認：1頁、9〜10頁。

- **概要：** 言語モデル呼び出し、記憶、保存、道具への接続を共通の中核層へ置き、複数の実行を管理する。
- **重要点：** 実行順の調整と資源分離を提供し、当該評価では処理の高速化・同時実行の改善を報告する。
- **限界：** 実行効率の改善は業務判断や機密保護の成立と別。名前が「OS」でも企業全体の運営を自動化する製品ではない。
- **示唆：** 共通 SDK だけに依存せず、呼び出しを受けるサーバー側でも権限・費用・停止を強制する。

## 2404.16130：文書群全体の傾向を関係グラフと要約から答える

原題：From Local to Global: A GraphRAG Approach to Query-Focused Summarization。[原文](https://arxiv.org/abs/2404.16130)、[PDF](arxiv/2404.16130/paper.pdf)。確認：1頁、12頁。

- **概要：** 文書から関係グラフを作り、まとまりごとの要約を利用して、資料全体の主題や傾向を問う質問へ答える。
- **重要点：** 個別箇所の検索と、資料全体の要約を区別する。包括性・多様性と、繰り返し質問した場合の費用を比較する。
- **限界：** 要約の評価は個別の法的結論の正しさと異なる。集約対象の権限や削除同期は別に設計が必要。
- **示唆：** 全社の傾向分析の候補だが、利用者が読めない文書を先に混ぜて要約しない。

## 2405.11706：知識構造を使って質問の誤りを検知・修正する

原題：Increasing the LLM Accuracy for Question Answering: Ontologies to the Rescue!。[原文](https://arxiv.org/abs/2405.11706)、[PDF](arxiv/2405.11706/paper.pdf)。確認：1頁、3頁。

- **概要：** モデルが作る検索式を、概念・関係の定義と照合して誤りを見つけ、説明を返して修正させる。
- **重要点：** 定義に合わない経路を検出する独立の検査を加える。修正できない場合を「不明」とする点も評価する。
- **限界：** 棄却と正答を同じ成功値へ混ぜずに読む必要がある。特定の業務質問での報告であり、任意の生成結果を保証しない。
- **示唆：** 文法検査に加えて意味の検査を行い、答えられない場合を明示して人へ返す。
