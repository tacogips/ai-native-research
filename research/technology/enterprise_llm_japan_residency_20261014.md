# 企業の機密情報管理におけるLLMの国内保存と処理地域

確認日：2026年10月14日。

企業が機密情報を大規模言語モデル（LLM）へ渡すときは、呼出先の地域名だけで安全性や国内処理を判断しない。**入力・出力の保存場所、推論と追加学習の処理場所、ログと補助機能、契約と利用権限を別々に確認する。** 本資料はTIMEWELLの公開記事を参照資料として登録し、公式仕様による確認と企業向けの運用案を分けて整理する。

## 参照する記事

- 題名：[国内リージョンでLLMは動かせるのか 各社の可用性と規制が本当に求めていること](https://timewell.jp/columns/llm-japan-region-availability-guide-2026)
- 発行：株式会社TIMEWELL。著者：濱本隆太。公開日表示：2026年9月5日。
- 位置付け：企業のAI基盤を提供する事業者による解説。法律や製品の公式仕様そのものとは区別する。

記事は、日本で呼び出せるモデルと国内で処理が完結するモデルを区別し、AWS・Azure・Google・Fireworksの提供方式を比較する。国内所在の要件を法令・業種・契約から判断し、モデルの版と移行可能性も確認することを提案している。企業の機密情報管理では、この問いを保存・処理・契約の具体的な確認へ落とし込む。

記事のモデル表は過去の取得時点の情報として扱う。本文には9月5日時点、AWS表の脚注には9月6日取得とあるため、表全体の取得日時を一つに統一したとは判断しない。現在の利用可否は対象モデルと提供形態を指定して確認する。

## 用語と判断の単位

| 用語 | 意味 | 判断を誤りやすい点 |
|---|---|---|
| リージョン | クラウドが提供する地域単位 | 東京のリソースや呼出先があるだけで全処理が東京になるとは限らない |
| エンドポイント | APIの呼出先 | 呼出先の地域と実際に処理される地域を区別する |
| データ所在の保証 | 保存または処理する地域を指定条件に限定する保証。data residencyと呼ばれる | 保存だけの保証か、モデル計算も含むかを確認する |
| 推論 | 入力から回答・分類等を生成する処理 | 追加学習に対応する地域表を推論へ流用しない |
| 追加学習 | 自社データ等でモデルを調整する処理。fine-tuningと呼ばれる | 学習データ、学習処理、学習済みモデルの配備先は別項目 |
| 地理的範囲内の振分け | 指定した範囲の複数地域で処理する方式 | 日本国内の振分けと、アジア太平洋全体の振分けは異なる |

## 公式仕様を確認した内容と記事の読み方

| 対象 | 公式資料で確認した内容 | 企業の機密情報管理での扱い |
|---|---|---|
| Amazon Bedrock | 指定地域内のIn-Region、地理的範囲内のGeo、世界規模のGlobalを区別する。モデルごとの対応表がある | 選んだモデルIDと推論プロファイル、振分け先の範囲を記録する。東京から呼べることと東京で処理されることを分ける |
| Microsoft Foundry | モデルと提供形態の対応を記載。記事で使う表は追加学習の節。保存・処理条件は別のデータ保護文書にも記載 | Global trainingの制約を、通常の推論全体へ一般化しない。対象モデルの推論配備方式と地理的処理範囲を別に確認する |
| Googleの生成AI基盤 | 呼出先だけでは所在や地域内計算を保証しないと記載。別の所在文書が保存とモデル計算の条件を分ける | 地域指定が無意味という結論にはしない。所在文書の対象モデル・機能・呼出方式を併せて確認する |
| Fireworks AI | 確認時点のOn-demand pricingに、地域制限付き配備の価格を1.5倍とする注記がある | 当該提供方式の条件として見積もる。全API・全契約・全地域へ一律適用しない |

出典：[Bedrock対応表](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)、[Foundryモデル](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/concepts/models)、[Foundryのデータ保護](https://learn.microsoft.com/en-us/azure/ai-foundry/responsible-ai/openai/data-privacy)、[Google呼出先](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/locations)、[Googleデータ所在](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/data-residency)、[Fireworks価格](https://fireworks.ai/pricing)。

Azureの公式文書は、GlobalまたはDataZone以外でも指定した地理的範囲の中で複数地域へ処理を移す場合を説明する。保存と処理の範囲、入力を基盤モデルの学習へ使わないこと、濫用監視や状態を保存する機能の条件を分ける。「学習に使わない」は「保存も閲覧も一切ない」と同義ではない。[Foundryデータ保護](https://learn.microsoft.com/en-us/azure/ai-foundry/responsible-ai/openai/data-privacy)

Googleの所在文書は、保存時の所在と計算時の所在を分け、対象機能とモデルの表を提供する。Global呼出先は世界のGoogle Cloud拠点で処理され得る。国内処理を要求する場合は、対応する保証条件と指定方法を確認する。[Googleデータ所在](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/data-residency)

特定の旧モデルへの地域配備を拡大しないという記述だけで、全モデルの将来の国内提供を予測しない。また、公開された重みを持つモデルでも、ホストする事業者と配備方式によって処理場所は変わる。国内に自社配備する方式と、事業者APIを利用する方式を分ける。

## クラウド向けQ&AをLLMへ適用する際の条件

個人情報保護委員会Q7-53は、保存データに個人データがあるかだけではなく、提供事業者がその個人データを取り扱うことになっているかを判断軸にする。契約と適切なアクセス制御により事業者が取り扱わない場合の説明である。Q7-54でも、利用者自身の安全管理措置は必要とする。[Q7-53](https://www.ppc.go.jp/all_faq_index/faq1-q7-53/)、[Q7-54](https://www.ppc.go.jp/all_faq_index/faq1-q7-54/)

**この条件を、外部のLLMへ個人データの本文を送って推論する契約に、確認なしで当てはめない。** 利用する処理、提供者・再委託先の役割、入力の保持と利用を確認し、委託・第三者提供・外国にある第三者への提供等の適用関係を判断する。学習への不使用だけでは、データを取り扱わない条件を満たすとは判断できない。

記事は医療・金融・政府調達等の要求にも言及する。民間企業へ政府の調達要件が一律に適用されるとも、特定の制度への登録だけで国内処理が保証されるとも考えない。自社に適用する制度・顧客契約・社内規程ごとに根拠と要件を整理する。関連する制度の出典を調べる際は、記事の脚注から原資料へ遡る。

## 企業で記録する確認項目

以下は公開比較に基づく運用案。モデル・機能・契約が変わったときにも再確認できる記録として使う。

| 確認軸 | 記録すること |
|---|---|
| 入力する情報 | 個人情報、企業秘密、顧客から預かった情報、契約上の利用制限 |
| 要求する境界 | 国内保存、国内処理、特定国を除く処理、外部への本文非送信等を区別 |
| モデルと呼出方式 | モデルIDと版、推論/追加学習、配備種別、呼出先、推論プロファイル |
| 本文の保存 | 入力・出力、添付、会話履歴、検索用データ、キャッシュ、バックアップ、保持期限と削除 |
| 実処理地域 | 推論、追加学習、埋め込み、画像/音声処理、濫用監視、障害時の振分け |
| 利用と閲覧 | 学習への利用、支援担当の閲覧、再委託、利用者と処理機の権限 |
| 秘密と鍵 | 鍵の取得先、版、取得権限。LLMの入力や一般ログへ鍵を含めない |
| 監査と移行 | 公式仕様の取得日・契約条件・設定変更、代替モデル、移行手順、再評価の契機 |

保存する地域だけを決めた場合は「国内保存」、推論も含めて制限した場合は対象処理を明記する。「国内で完結」という記述を、確認済みの範囲より広く使わない。国外処理を許可する例外は、対象情報・目的・送信先・責任者・保持条件を明示する。

モデル変更時は精度と料金だけでなく、地域保証・状態保存・濫用監視・機能の追加送信先を再評価する。機密な本文を残さずに、許可した配備先と実行した設定を追跡できる記録を設計する。
