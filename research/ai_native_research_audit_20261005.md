## 出典の検証区分

- **本文確認:** Web で取得した公式 docs / 企業発表本文。記述を確認したが製品を動かしていない。
- **研究確認:** 下表の通り、abstract・研究者の説明・本文のいずれか。研究の保証や率はその脅威モデル・評価条件に限定する。
- **公式検索掲載:** 正式ドメインの検索に掲載された本文抜粋を確認。直接取得できないため全条文や現行画面は精読できていない。
- **二次:** Klarna CEO の発言報道。現行運用の結論は20-Fと区別する。
- **設計案:** 社内構成、PoC、SDK、各業務フロー、昇格条件、監査・停止。実装再現の証拠とはしない。

## 写真の主張から修正・限定したもの

1. AI-native / 完全自律の目標を AI-only 達成と扱わない。Harper / Panta は人の高リスク gate を明示する。
2. Panta は保険企業として特定し、同名の金融 platform と混ぜない。創業年の資料差は保留する。
3. Temporal に Workflow を置くことと CaMeL の安全保証を同一視しない。出所・宛先・副作用の検査が必要。
4. Mem0 の現行 add docs は追加型。過去の更新・削除挙動を現行仕様として再利用しない。
5. 国内 AI ガイドラインは第1.2版、法務省の72条指針は2026年拡充を確認。旧版だけの評価にしない。
6. Klarna の「撤回」報道に加え現行年次報告の dual-track を確認。AI と人の併用を記述する。
7. METR の2025年19%遅延には時点・対象の限定と2026年の測定限界を添える。
8. KIRIN / Totoro と年内 PoC は社内条件・設計仮説。公開資料からの実現・期限の保証はしない。

## 調査成果と導入検証の区別

今回の成果は、写真の10テーマ全項目に対応した公開資料の再調査、比較・設計案、出典と限界の repo 内レポートである。以下は自社導入を決める際の次段階であり、今回実行したと記述しない。

- 社内仕様・権限・契約を確認し、KIRIN / Totoro と connector の接続を試験する。
- 日本語法務データで品質・例外・費用・待ち時間・ACL 失効・停止・再開を検証する。
- 新 MOJ / AI 指針の本文と社内基準を専門家が照合する。
- 専用 legal-tech の見積り・region・保持・API・export・責任範囲を契約で確定する。

出典の限界を記したことは「導入してよい」の証明ではない。研究結果から設計を比較できる状態にすることと、本番自律運用の成立を証明することを分けている。
