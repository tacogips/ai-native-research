# 最近5年の大規模な個人情報流出・事故：原因、事後調査、再発防止と取扱いの改善

調査日：2026年10月8日。対象期間：2021年10月8日～2026年10月8日。

## 読み方と選定範囲

日本10事例（うち尼崎市は紛失の比較事例）、海外16事例を詳しく比較し、Ticketmaster・Co-opを補足した。Money Forwardの2026年GitHub事件を追加した。大規模な影響、医療・遺伝・通信・児童情報等の重大な機密性、あるいは詳しい公的事後調査の存在を基準に選定した。全世界の全事件の網羅や被害規模の順位ではない。国内外の被害人数を合算しない。

侵入・公開状態が期間前に始まっていても、期間内に継続・発覚したNTT、トヨタ、SK Telecomを含め、開始時期を明記した。2021年8月発生のT-Mobile事件は期間外なので、ここでは2022年11月以降の別事件を扱う。

「流出確認」は公表資料で不正取得・公開が確認されたもの。「可能性」は取得を排除できない範囲。「公開可能」は設定上の閲覧可能状態で、実際の取得を意味しない。「件」「人」「アカウント」「文書」は別単位であり置き換えない。公表情報の全てが全対象者に同じように流出したわけではない。

**各事例の「公表された対策」は組織・当局の説明。「取扱いの改善」は本調査の提案である。** 提訴中の主張、当局の最終認定、企業説明、実施済み、計画・命令を分けた。原因未特定は未特定のまま残し、事故発生だけで違法・過失としない。最新の公表資料を選んだが、非公開の訴訟・実装・全ての後続発表を監査したものではない。主な根拠の時点は各事例に記載した。

事後調査（postmortem）は、何が起こり、なぜ防御が機能せず、何を変えたかを分析する報告。技術的な初期侵入だけでなく、被害を拡大した管理と対応の失敗を含む。

## 用語

| 用語 | 意味 |
|---|---|
| 多要素認証（MFA） | パスワードに加え、所持する機器等の異なる要素で本人を確認する仕組み |
| VPN | 遠隔接続を保護する通信経路。認証・機器の欠陥や過剰権限があれば侵入経路になる |
| API | 外部プログラムが情報取得や操作を要求する接続口 |
| EDR | 端末・サーバーの不審な挙動を検知し、隔離等へつなぐ仕組み |
| 最小権限 | その人・処理が必要とする情報と操作だけを許可する原則 |
| ネットワーク分離 | 一つの侵害から別の重要システムへ移動できる範囲を制限すること |
| トークン／署名鍵 | 認証済み等を示すデータと、その真正性を検証できる形で作る秘密の鍵 |
| 証拠保全 | 調査に必要な記録を変更・削除されないよう確保すること |
| 情報保護責任者（CPO） | 組織の個人情報管理を統括する責任者 |

## 日本の10事例

### J01 NTT西日本グループの顧客情報持ち出し

**時期・規模・状態：** 2013年7月～2023年2月、2023年発覚。約928万人、69委託元。流出確認。

**原因：** 保守業務の従事者が顧客情報を私有USBへ不正に保存。共有管理者アカウント、全顧客を横断する権限、持ち出し制限とログ監査の不足が長期間の不正を許した。

**事後調査・証拠の限界：** 個人情報保護委員会（PPC）の2024年1月調査と9月の是正確認が詳しい。2022年に顧客から依頼された調査は表面的で、ログの一部改変と虚偽回答もあった。漏えいを認識して意図的に隠蔽した形跡とは区別されている。

**公表された対策・実施状況：** 2024年9月資料で、私有USB接続防止、保守端末へのダウンロード禁止、保守担当の取得権限廃止、多要素認証、USB利用の複数承認などの実施を確認。監視強化などには推進中の項目もある。

**取扱いの改善（本調査の提案）：** 委託元・案件単位で権限を分け、保守は本文取得を原則不要にする。一括取得は別承認と即時監視を必須にし、顧客の指摘を営業部門から独立して再調査する。

根拠：[NTTグループ不正持出し・PPC詳細調査](https://www.ppc.go.jp/files/pdf/240124_houdou.pdf)、[PPC勧告等に対する是正状況](https://www.ppc.go.jp/files/pdf/240911_shiryou-2-2.pdf)。

### J02 LINEヤフー

**時期・規模・状態：** 2023年9～10月侵入（PPCの認定では、起点となった委託先A社への不正アクセスは2023年8月10日と24日、LINEヤフーのシステムへの侵入は9月14日〜10月27日（2026-10-08の深掘りで補足: [詳細](../incidents/japan_data_leaks.md)））、2024年2月範囲更新。519,506件。利用者302,980件、取引先86,211件、従業者130,315件。確認・可能性を含む公表範囲。

**原因：** 委託先の端末への悪意あるプログラムの感染を起点に、NAVER Cloudとの共有認証と広いネットワーク接続が侵入の拡大を許した。

**事後調査・証拠の限界：** 会社の最終範囲調査とPPC向け改善結果を照合。利用者情報のうち日本分は130,192件。人数への換算はしない。トーク本文やカード・銀行情報の流出とは会社は報告していない。

**公表された対策・実施状況：** 2026年7月更新で、国内外の対象子会社を含む認証・ネットワーク・システム分離を3月に完了、残る一時バックアップを6月に削除と説明。全社多要素認証や国内の独立監視体制も実施。管理端末制限には承認された例外がある。

**取扱いの改善（本調査の提案）：** 委託先との共有認証を避け、接続ごとに必要な範囲だけ許可する。データ分離の完了には通常環境だけでなく一時コピー・バックアップの削除も含める。

根拠：[LINEヤフー影響範囲の最終調査](https://www.lycorp.co.jp/ja/news/announcements/007712/)、[LINEヤフー再発防止策の実施結果・2026年7月](https://www.lycorp.co.jp/ja/privacy-security/recurrence-prevention/ppc/)、[LINEヤフー当局への報告完了・2026年7月](https://www.lycorp.co.jp/ja/news/announcements/020659/)。

### J03 トヨタ／Toyota Connectedのクラウド設定

**時期・規模・状態：** 2013年11月～2023年4月に公開可能、2023年5月公表。約215万人分の対象情報（5月12日公表分）。PPCの2023年7月12日の指導は、5月31日公表の国内分（約26万人）と一つの事案として扱い約230万人分と記載する（両者の重複は不明）（2026-10-08の深掘りで訂正: [詳細](../incidents/japan_data_leaks.md)）。外部閲覧可能、第三者の取得未確認。

**原因：** クラウドの公開設定の誤りが長期間残った。PPCは委託元の設定確認・委託先監督の不足を指摘。車載端末識別子、車台番号、位置情報・時刻等が対象。

**事後調査・証拠の限界：** 会社公表と2023年7月のPPC資料で管理上の原因を確認。公開可能な状態と実際の持ち出しは別。2022年のソースコード公開は同じ人数に合算しない。2023年5月31日公表の国内分は会社公表では別件だが、当局は同一事案として約230万人分と集計したため、両方の数を出典付きで併記する。

**公表された対策・実施状況：** 会社は設定を非公開化し、クラウド設定の監査・継続監視や管理体制強化を公表。PPCは委託先の取扱い状況の把握、教育、監督を求めた。長期の再発ゼロを独立検証したものではない。

**取扱いの改善（本調査の提案）：** 公開禁止を初期設定とし、設定変更を自動検査する。外部から閲覧できないことも実測する。氏名がなくても位置履歴と識別子を組み合わせる危険を評価する。

根拠：[トヨタ215万人のクラウド公開設定](https://global.toyota/jp/newsroom/corporate/39174380.html)、[トヨタPPC行政対応](https://www.ppc.go.jp/files/pdf/230712_01_houdou.pdf)、[トヨタ再発防止策](https://global.toyota/jp/newsroom/corporate/39529198.html)。

### J04 KADOKAWA／ドワンゴ

**時期・規模・状態：** 2024年6月8日発生、8月5日調査結果。254,241人（2024年8月5日時点）。2024年11月1日時点で261,956人へ更新（7,715人追加。会社は追加分も6月8日以前の窃取と説明）（2026-10-08の深掘りで訂正: [詳細](../incidents/japan_major_ransomware.md)）。流出確認。

**原因：** 従業員の認証情報を不正利用した侵入が疑われるが、取得方法は特定されていない。会社は「経路および方法は不明」としつつ、「フィッシングなどの攻撃により従業員のアカウント情報が窃取されたことが根本原因と推測」と述べた（2024年8月5日報告）。身代金を要求する攻撃で、学校関係者・取引先・従業者等の情報が流出した。

**事後調査・証拠の限界：** 会社の2024年8月5日報告で対象範囲を確認。学校関連の情報も含む一方、ニコニコのログイン情報や保有していないカード情報の流出とはしない。侵入手口の確定した詳細事後報告は今回の資料にない。

**公表された対策・実施状況：** 対象者通知、相談窓口、流出情報の削除・拡散抑制、外部専門家による調査・安全性確認を公表。2025年6月の有価証券報告書で監査法人が「サイバーセキュリティに関する内部統制の不備」の是正を確認し（不備の中身は非公表）、2026年6月の有価証券報告書はゼロトラスト前提の認証基盤、EDR/XDR、SOCの24時間365日監視を記載する。多要素認証の個別の記載は依然ない（2026-10-08の深掘りで訂正: [詳細](../incidents/japan_major_ransomware.md)）。

**取扱いの改善（本調査の提案）：** 学籍・応募者・人事・取引先のファイルを業務別に隔離し、通常利用者の取得範囲を絞る。退学・退職・不採用後の保存期限と作業コピーの削除を定める。

根拠：[KADOKAWA調査・影響範囲・2024年8月](https://group.kadokawa.co.jp/information/media-download/1356/d3f77b589c58d083/)。

### J05 イセトー

**時期・規模・状態：** 2024年5月26日発生、2025年3月19日PPC指導（個人情報保護法147条。調査結果の公表であると同時に行政上の指導）（2026-10-08の深掘りで訂正: [詳細](../incidents/japan_major_ransomware.md)）。委託対象3,076,477人、別に従業者441人。要配慮情報13,150人は内数。漏えい・毀損確認。

**原因：** VPNの更新が2021年4月から止まり、管理者パスワードが弱く多要素認証もなかった。ログ不足により最初の侵入方法には不確実性が残る。PPCの認定では、56部署中3部署が業務データの共有や発送管理の目的で、本件個人データを基幹系ネットワーク上のサーバーへコピーしていた（「検証用データ」は会社説明の「帳票データや検証物の一部」に由来し、PPC認定より狭い（2026-10-08の深掘りで訂正: [詳細](../incidents/japan_major_ransomware.md)））。保存・削除ルールも守られなかった。

**事後調査・証拠の限界：** 会社の調査完了公表とPPCの7頁の認定が対応。処理設備の一部が適切に守られても、管理区域の外に置いた二次コピーから大規模な被害になり得ることを示す。

**公表された対策・実施状況：** 会社はVPN撤去、認証・外部接続制限の強化を説明。データ持ち出しの制限、保存期限に基づく削除、監査・教育を再発防止策に掲げた。全ての施策の長期運用完了とは読まない。

**取扱いの改善（本調査の提案）：** 検証データも原本と同じ区分で管理し、可能なら合成データへ置換する。コピー先と削除期限を機械的に管理し、委託元は実際の保存場所・削除証跡を確認する。

根拠：[イセトー調査完了・原因と再発防止](https://www.iseto.co.jp/news/news_202410.html)、[イセトーPPC指導（法147条）・2025年3月19日](https://www.ppc.go.jp/files/pdf/250319_houdou.pdf)。

### J06 アスクル

### J10 Money ForwardのGitHub不正アクセス

2026年5月1日公表、6月23日に調査完了を公表。漏えいした認証情報でGitHubへ不正アクセスされ、プログラムや関連ファイルを保管するリポジトリがコピーされた。初報ではビジネスカード370件の保持者名・番号下4桁が流出した可能性を説明した。全桁番号・有効期限・セキュリティコードの流出は確認されていない。[第一報](https://corp.moneyforward.com/news/info/20260501-mf-press-1/)。

6月の追加精査では、顧客の氏名・メール124人、取引先28人、従業者2,300人、顧客の管理用固有識別子60,449人を公表した。従業者の項目別件数には重複があり、2,300人は名寄せ後。管理用識別子はログインIDではない。初報の370件や追加区分を一意人数として合算しない。会社は本番環境への不正アクセス・情報流出と二次被害を否定している。[第四報](https://corp.moneyforward.com/news/info/20260623-mf-press-1/)。

安全性確認のため銀行連携を停止し、5月12日から順次再開。Money Forward MEでは6月5日10時50分にすべての銀行連携再開と説明する。各銀行が同じ期間停止したという意味ではない。公開情報に暗号化や身代金要求の確認はなく、ランサムウェア事例として計上しない。[第三報](https://corp.moneyforward.com/news/info/20260512-mf-press-1/)、[再開状況を含む質問と回答](https://support.me.moneyforward.com/hc/ja/articles/57548547365145)。

第二報は認証情報の無効化・再発行、最小権限への変更、安全性再検査に加え、保存時の機密情報の機械的な監視を開発手順に組み込んだと説明する。第四報は端末・外部通信の統制、開発環境の監視、体制・教育の整備と、技術的検知の継続強化を説明する。機械的な監視の実施は公表されているが、使った製品・AIの有無・検知対象・阻止の強制力・精度は公表資料から分からない。[第二報](https://corp.moneyforward.com/news/info/20260511-mf-press-1/)、[第四報](https://corp.moneyforward.com/news/info/20260623-mf-press-1/)。

**自社への改善提案：** 本番データだけでなく更新作業の一時ファイル・試験資料・変更履歴も機密検査の対象にする。個人情報と認証キーは別々に検知し、端末での事前検査と保管先での強制検査を組み合わせる。認証情報は短い有効期限と最小権限にし、盗まれたときの一括失効を準備する。書式検査で分かるメール・電話・カード情報と、文脈が必要な氏名・管理番号を分けて評価する。この事例からローカルの大規模言語モデルの採用や精度優位が証明されるわけではない。

### F01 Robinhood

**時期・規模・状態：** 2021年11月3日発生。メール約500万人＋別の氏名約200万人。310人に追加項目。流出確認。

**原因：** 電話で顧客サポート従業員をだまし、サポート用システムへアクセスした。SECは2025年の和解命令で、既知のリモートアクセスの危険へ2021年6～11月に十分対応しなかったと認定した。これは被処分者が認否しない前提の和解上の認定である。同命令は、2021年6月14日に同種の事故があり、その是正措置が不完全なまま11月に再発した点も認定している（SEC和解命令 34-102170 ¶74–77（2026-10-08の深掘りで訂正: [詳細](../incidents/global_consumer_data_breaches.md)））。

**事後調査・証拠の限界：** 会社の届出とSECの後年の調査を組み合わせる。社会保障番号、銀行口座、デビットカードの流出は会社が否定。4,500万ドルの制裁は複数の法令違反を対象とし、この事件だけの罰金ではない。

**公表された対策・実施状況：** 会社は侵入の封じ込め、Mandiantを交えた調査、捜査機関への連絡・本人通知を公表。詳細な設計変更や全再発防止策の完了は今回の資料で未確認。

**取扱いの改善（本調査の提案）：** サポート担当が全利用者を一括取得できない設計にし、電話での権限変更は既知の連絡先による別確認を要求する。既知の危険の期限・責任者・対応証拠を追跡する。

根拠：[Robinhood 2021年11月事故公表](https://investors.robinhood.com/static-files/f15cea1a-1fd4-4634-b2a4-3b7523b48c11)、[Robinhood SEC 2025年調査結果](https://www.sec.gov/newsroom/press-releases/2025-5)。

### F02 Optus

**時期・規模・状態：** 2022年9月発覚。約950万人（OAICの主張する個人数。会社は「顧客レコード980万件」と説明しており単位が異なる）。流出確認。2024年ACMA提訴・2025年OAIC提訴の主張を含む（2026-10-08の深掘りで訂正: [詳細](../incidents/global_consumer_data_breaches.md)）。

**原因：** 外部公開された経路から顧客情報が不正取得された。OAICより前に、ACMAが2024年5月22日に連邦裁判所へ提訴し、流出期間を2022年9月17〜20日と主張した（[ACMA声明](https://www.acma.gov.au/acma-statement-2022-optus-data-breach)）。OAICは2025年の提訴で合理的な安全措置の不足を主張。今回確認した公表資料だけではAPI実装の欠陥を詳細に確定できない。

**事後調査・証拠の限界：** 当局は現在・過去・見込み顧客の氏名、連絡先、生年月日や政府発行の識別番号を対象として調査。提訴を裁判所の確定判断と表現しない。

**公表された対策・実施状況：** 当局は公開ドメインの棚卸し、内部・外部経路の把握、権限・多層防御・監視・人員体制を改善の指針として提示。今回資料では全措置の企業側の実施完了を確認できない。

**取扱いの改善（本調査の提案）：** 本人確認書類の番号を漫然と保存しない。公開サービスから内部の顧客情報へ届く経路と所有者を台帳化し、各要求の取得権限を検査する。

根拠：[Optus OAIC調査・提訴と改善の指針](https://www.oaic.gov.au/news/media-centre/australian-information-commissioner-takes-civil-penalty-action-against-optus)。

### F03 Medibank

**時期・規模・状態：** 2022年8～10月侵入、11月流出情報公開。約970万人。流出確認。具体的過失の記載は当局の裁判上の主張。

**原因：** 当局提出資料では、委託先担当の業務用認証情報が私用端末へ同期され、窃取プログラムに取得された。多要素認証のないVPN、広い管理者権限、対応されない検知警告が侵入・取得を許したと主張。

根拠：[Medibank規制当局の裁判所提出資料](https://www.oaic.gov.au/__data/assets/pdf_file/0025/221974/Australian-Information-Commissioner-v-Medibank-Private-Limited-concise-statement.pdf)、[Medibank OAIC提訴](https://www.oaic.gov.au/news/media-centre/oaic-takes-civil-penalty-action-against-medibank)、[Medibank Deloitte事後調査の説明](https://www.medibank.com.au/livebetter/newsroom/post/cybercrime-update-deloitte-incident-review)。

### F04 T-Mobile

**時期・規模・状態：** 2022年11月25日から、2023年1月5日発覚。約3,700万アカウント。流出確認。人数とは区別。

**原因：** APIを通じた不正な情報取得。会社は発覚から24時間以内に遮断と説明。FCC同意判決（DA 24-860 ¶24）は、人為的ミスにより権限設定が誤って構成され、攻撃者が照会を送って顧客アカウントデータを取得できたと記載しており、原因は「権限設定の誤り（人為的ミス）」と書ける（2026-10-08の深掘りで訂正: [詳細](../incidents/global_consumer_data_breaches.md)）。

**事後調査・証拠の限界：** 会社公表・四半期報告とFCCの2024年の合意を確認。氏名・住所・生年月日等が対象だが、会社は今回のAPIにはパスワード、社会保障番号、決済情報等が含まれなかったとする。

**公表された対策・実施状況：** FCCとの合意は複数年の複数事件を対象に、必要な通信・操作ごとに権限を検証する設計、なりすましに強い多要素認証、統治強化への投資を求める。この事件単独の措置や完了証明としない。

**取扱いの改善（本調査の提案）：** ログイン時だけでなく、APIが各顧客レコードを返す時点で権限を検査する。大量取得の速度・件数を制限し、通常利用との差を監視する。

根拠：[T-Mobile 2023年事故公表](https://www.t-mobile.com/news/business/customer-information)、[T-Mobile 2024年第1四半期報告書・3700万アカウント](https://investor.t-mobile.com/files/doc_financials/2024/q1/Q1-2024-10-Q_vFinal.pdf)、[FCC T-Mobile再発防止合意](https://docs.fcc.gov/public/attachments/DOC-405937A1.pdf)、[FCC T-Mobile合意本文](https://docs.fcc.gov/public/attachments/DA-24-860A1.pdf)。

### F05 23andMe

**時期・規模・状態：** 2023年4～9月侵入、10月発覚。世界で約700万人。英国155,592人等は内数。流出確認。情報の種類は利用者ごとに異なる。

**原因：** 他サービスから流出した認証情報の使い回しを狙う攻撃。親族探索・家系共有の機能を通じ、直接侵害されたアカウントを超えて被害が拡大。警告と大量アクセスの検知対応も不十分だった。

**事後調査・証拠の限界：** 英加共同調査が原因・通知・改善を詳細に分析。一部の直接侵害アカウントでは健康情報や生のDNAデータも対象。約700万人全員のDNA配列が流出したとはしない。

**公表された対策・実施状況：** ログイン時の認証追加（全利用者への2段階認証の義務化は2023年11月6日。8-K/A（2026-10-08の深掘りで補足: [詳細](../incidents/global_consumer_data_breaches.md)））、監視・防御、対応手順を2024年末までに改善。共同調査は確認した問題への改善が提言を満たすと評価。2025年ICOの確定制裁は231万ポンド。将来の全リスク消失の保証ではない。

### F06 Capita

### F15 Qantas

**時期・規模・状態：** 2025年6月28～30日、2026年7月16日予備調査報告公表（予備調査の期間は2025年7月11日～2026年6月1日（2026-10-08の深掘りで訂正: [詳細](../incidents/us_supply_chain_breaches.md)））。約567万顧客レコード、豪州の約512万人。流出確認。レコードと人を区別。

**事後調査・証拠の限界：** OAICの2026年7月16日公表の予備調査報告は、不正な指示から取得までを説明。合理的措置の欠落等を疑う根拠を見いださず、本格調査を開始せず終了。事故が起きたことだけで法令違反や過失と断定しない。

**公表された対策・実施状況：** アカウント停止・接続解除、専門家調査、本人通知、追加研修を実施。顧客管理製品の提供者も全顧客向けの初期設定を変更。調査終了は全危険がないことの証明ではない。

**取扱いの改善（本調査の提案）：** 一般担当者による外部アプリ接続を制限し、取得可能な項目と範囲を管理する。医療AIや業務AIの道具接続でも同じ操作制限が必要。カード等を当該環境に保存しない設計は被害縮小に役立つ。

根拠：[Qantas OAIC 2026年予備調査全文](https://www.oaic.gov.au/privacy/privacy-assessments-and-decisions/privacy-decisions/Investigation-inquiry-reports/report-into-preliminary-inquiries-of-qantas)、[Qantas 2025年7月事故通知](https://www.qantas.com/agencyconnect/global/en/agency-news/agency-news-july-25/qantas-cyber-incident.html)。

### F16 PowerSchool

**時期・規模・状態：** 2024年8月16日～9月17日に同じ認証情報による不審な接続（CrowdStrikeは12月の攻撃者と同一とは確認できず、起訴状は被告人が9月4日に侵入したと記載（2026-10-08の深掘りで訂正: [詳細](../incidents/us_supply_chain_breaches.md)））、12月19～28日侵害、2025年1月通知。Ontario州約386万人。カナダ全体は数百万人、世界の一意人数は本資料で未確定。流出確認。

**原因：** 委託担当の認証情報でサポート基盤へ入り、生徒情報管理の各顧客環境から取得。認証情報の取得方法は不明。サポート基盤に多要素認証がなく、権限が広く、学校側の過剰収集・長期保存も被害を増やした。

**事後調査・証拠の限界：** Ontario州当局の55頁報告は学校側の契約・監督・保存を分析。OPCとの約束は会社の責任承認ではなく改善の合意。連邦の調査終了と州当局の違反認定・調査は対象が異なる。

**公表された対策・実施状況：** 侵害アカウント停止、全認証情報更新、認証追加付きVPN経由へのアクセス制限は実施と説明。監視・権限見直し、独立評価、認証更新の証拠提出は期限付き約束。2026年3月期限の全履行は今回未確認。

**取扱いの改善（本調査の提案）：** 学校の保守アクセスを依頼時だけ有効にし、医療注意情報・識別番号を目的に必要な分だけ保存する。契約上の権利に加え、監査資料の取得・是正追跡・終了時削除を実施する。

根拠：[PowerSchool OPC改善約束](https://www.priv.gc.ca/en/opc-news/news-and-announcements/2025/let_powerschool_20250715/)、[PowerSchool Ontario詳細事後調査・55頁](https://www.ipc.on.ca/media/5990/download)。

|---|---|---|

### 個人情報の扱いで特に変える点

「データベースが暗号化されているか」だけで評価せず、誰が復号後の情報を取得できるか、通常業務から全件取得できるか、不要なコピーが残っていないかを調べる。Coupangでは認証を作る鍵の管理、Qantasでは正規画面からのアプリ接続が問題となった。暗号化と多要素認証だけで全ての取得経路を閉じたことにはならない。[Coupangの当局調査](https://pipc.go.kr/eng/user/ltn/new/noticeDetail.do?bbsId=null&nttId=3071)、[Qantasの予備調査](https://www.oaic.gov.au/privacy/privacy-assessments-and-decisions/privacy-decisions/Investigation-inquiry-reports/report-into-preliminary-inquiries-of-qantas)

医療・遺伝・児童・通信履歴には、本人が変更できない情報や関係者にも波及する情報がある。単に氏名を消したことを安全性の証明にせず、位置・家系・識別番号の組合せも評価する。事故通知は項目別の危険を説明し、遺伝・健康情報を「一般的なプロフィール」とまとめない。[23andMe共同調査](https://www.priv.gc.ca/en/opc-actions-and-decisions/investigations/investigations-into-businesses/2025/pipeda-2025-001/)

### local LLM・外部AI・秘密計算への示唆

手元の環境で動くLLM（文章を処理・生成する大規模言語モデル）でも、委託先の保守権限、取得用API、共有ドライブ、ログに本文が残れば情報は持ち出され得る。PowerSchoolの州当局報告では、クラウド保存と学校内保存の双方で、遠隔保守を許可した環境が侵害された。配置場所だけを安全性の判断基準にしない。[Ontario州報告、17～18頁](https://www.ipc.on.ca/media/5990/download)

外部AIを利用する場合、入力の機密性検出に加え、検索時の権限、全宛先、添付、接続する道具、出力先を制限する。検査を迂回するAPI送信や、AI以外のデータ取得も管理する。今回の事件群から「AIによる分類を入れれば防げた」「local LLMの方が検出精度が高い」とは実証できない。

暗号化したままの計算や、運営者から内容を隔離する処理は開示先を減らす選択肢になるが、入力前の原本、秘密の鍵、出力、管理者権限、不要な保存にも対策が必要。これらの事件をゼロ知識証明で一般的に防げるとの結論は出せない。技術の対応範囲は[平文を開示しない分類](confidentiality_classification_without_plaintext_20261007.md)と[ゼロ知識証明の調査](zero_knowledge_sensitive_data_research_20261007.md)に分けて整理している。

## 日本と海外の公表資料から学ぶ違い

今回の選定では、日本のPPC資料は委託関係、技術・組織面の安全管理、削除や持ち出しの規則が実際に守られたかを具体的に追える。NTTの是正状況は、命令だけでなく実装の確認まで読む価値がある。海外では23andMe、Capita、PSNI、PowerSchoolの当局資料が、認証・権限・監視・契約・通知を長い事後調査として公開している。

ただし、選定資料の公開の詳しさを、国全体の安全性・事故頻度・制度の優劣と置き換えない。Medibank・Optusの提訴内容と、ICO・CNILの最終制裁、Qantasの予備調査終了では法的な状態も違う。制裁額をそのまま被害の大きさ・対策の良さの順位にしない。制度の比較は[日本・海外の個人情報管理資料](../disclosures/privacy_data_management_reading_summary_20261007.md)を参照。
