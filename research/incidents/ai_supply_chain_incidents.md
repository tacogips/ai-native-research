# AIツール・連携に関わるソフトウェア供給網と委任用認証情報の事案

記述の水準: 共通仕様の追加規則（2026-10-08）に従い、侵入経路は「どの防御・統制が欠けていたか、どこで止められたか」の水準で書く。攻撃の手順、コマンド、悪性コードの内容、窃取・送出の手法、攻撃基盤の識別子は記載しない。それらは各出典の一次資料にあるが、本書では要約もしない。

用語:
- **供給網攻撃**（サプライチェーン攻撃）: 利用者が信頼している配布元・部品・連携先を経由して、利用者側へ不正なコードや不正なアクセスを届ける攻撃。
- **委任用認証情報**: 利用者本人の代わりに外部サービスへアクセスするために発行される鍵。OAuth のアクセストークン（短期の利用許可証）とリフレッシュトークン（許可証を再発行するための長期の鍵）、個人アクセストークン（PAT）、API キーなどを含む。
- **npm**: JavaScript の部品（パッケージ）配布基盤。部品の導入時に自動で処理を実行する仕組みがある。
- **CI**: 継続的インテグレーション。コードの変更ごとにビルドや配布を自動で行う環境。
- **provenance（来歴証明）**: その配布物がどのソースコードとどの CI から作られたかを署名付きで示す記録。**Trusted Publishing** は、長期の配布用トークンを使わず、CI から短期の証明書で配布する npm の方式。
- **MCP サーバ**: AI アシスタントが外部ツールを呼び出すための Model Context Protocol に従う接続部品。

## このグループの要点

1. 6件すべてで、攻撃者は「利用者が信頼して自動的に取り込む経路」を使った。Nx・Amazon Q・Bitwarden は配布元の CI や配布用トークンの奪取、node-ipc は休眠した保守者アカウント、postmark-mcp は公式を装った偽パッケージ、Salesloft Drift は連携先が保管していた OAuth トークンである。
2. AI ツールが攻撃に組み込まれた事実を一次資料で確認できたのは3件である。Nx では、利用者端末の AI CLI を確認なしで動かす設定で起動し、秘密情報の探索に使った。Amazon Q では、AI CLI に破壊的な操作を指示するコードが混入したが、AWS によれば実行に失敗した。Bitwarden CLI では、AI エージェントと MCP の設定ファイルが収集対象に含まれていた（JFrog の解析）。
3. AI 連携製品そのものが侵害の入口となったのは Salesloft Drift（AI チャットボット）と postmark-mcp（MCP サーバ）である。ただしどちらも、言語モデルへの不正指示（プロンプトインジェクション）が原因ではない。前者は開発基盤（GitHub と AWS）の侵害によるトークン窃取、後者は悪意ある配布者による改変である。
4. 被害の規模は「配布された」「実行された」「情報が実際に取られた」で大きく異なる。Amazon Q は配布されたが実行に失敗した（AWS の説明）。node-ipc は収集能力が確認されたが、被害者側での実行と受信は確認されていない（独立報告書の評価）。Nx は GitGuardian が流出秘密情報 2,349 件を数えた。
5. 委任用認証情報の連鎖が被害を広げた。Nx では、第1段で流出した GitHub トークンが第2段で非公開リポジトリの公開に使われた。Salesloft Drift では、顧客の問い合わせ本文に含まれていた他サービスの鍵が狙われた。
6. 刑事手続きは TeamPCP 関連で動いた。米司法省は2026年8月27日に起訴を公表した。ただし公表文は Bitwarden も node-ipc も名指ししておらず、両事案との結び付きは研究者や保守者の見解にとどまる。民事では Salesloft に対する集団訴訟8件が2025年12月19日に併合された。
7. 既存記述の訂正候補は7件ある。主なものは、Salesloft Drift の「700超の組織から流出」の出典と性格（FBI 資料には数がなく、Google の「影響を受けた可能性」の推計である）、Amazon Q の「95万インストールに配布」、Bitwarden の「334件」の出典と「AI 設定ファイル標的は未検証」の判断、node-ipc の勧告番号の範囲である。

#### 3. 欠けていた統制と止められた箇所

- **CI の入力処理と権限（Nx の説明）**: 外部の PR から来る情報を無害化せずに扱うワークフローがあった。そのワークフローは高い権限で動いていた。リポジトリ既定の Actions 権限は「読み書き」で、配布用ワークフローは手動起動も可能だった。Nx は「信頼された環境に入れれば npm に配布できてしまう構成が決定的な誤りだった」と述べている。
- **配布の統制（Nx の説明）**: 長期の npm 配布用トークンが CI に置かれていた。攻撃者はこのトークンでリリース手順を迂回した。来歴証明は付いていなかったが、npm は来歴証明のない版の導入を止めないため、利用者側では防げなかった。
- **利用者端末の統制（Nx 勧告と研究者）**: 悪性版は導入時に自動実行される処理で端末内の秘密情報を探した。その際、端末にある AI CLI を確認なしで動く設定で起動した。AI CLI が組織の方針で確認省略を禁止されていなかった端末では、エージェントが探索に使われた。
- **止められた箇所（研究者）**: GitGuardian によれば、LLM ツールの利用が試みられた 366 台のうち、指示どおりに動いたのは 95 台だった。Wiz は「AI 事業者の安全機構が介入した場合もあった」と述べている。npm による削除と GitHub による公開リポジトリの無効化で、第1段は約半日で抑えられた。
- **第2段**: 流出した GitHub トークンの権限が広く、失効も遅れたため、非公開リポジトリの公開に使われた。

#### 4. 影響

- 個人・組織: 流出した秘密情報は GitHub、npm、AWS、OpenAI の鍵が多かった（GitGuardian）。有効なまま残った鍵のうち最多は GitHub OAuth アプリの鍵だった。感染端末の 85% は macOS だった（GitGuardian）。
- 第2段では企業の非公開コードと秘密情報が公開された。GitGuardian は第2段で 82,901 件の秘密情報（うち有効 11,168 件）を検出した。数値は集計者と時点で異なり、Wiz は 2025-08-29 14:00 UTC 時点で 5,500 超のリポジトリとしている。
- Nx Cloud は影響を受けていない（Nx 事後報告）。

#### 9. 企業AI基盤への教訓（本調査の推論）

- **AI CLI の確認省略モードは、攻撃者にとっての「端末内探索サービス」になる。** 開発端末の AI エージェントは確認省略を既定で使えないようにし、組織の設定で上書きを禁止する。
- **CI の権限を最小化する。** 外部 PR を高権限で処理しない。既定トークンは読み取り専用にし、配布ワークフローの手動起動は無効化する。
- **配布用の長期トークンを廃止する。** Trusted Publishing と来歴証明を必須にする。利用側は来歴証明のない新版を自動で取り込まない。
- **盗まれたトークンの二次利用を想定する。** GitHub の PAT は対象リポジトリと権限を絞り、可視性の変更などの危険操作に追加承認を求める。

#### 3. 欠けていた統制と止められた箇所

- **開発基盤のアクセス管理（Mandiant の結論、Salesloft が公表）**: 起点は Salesloft の GitHub アカウントへの不正アクセスで、PAT が使われた。PAT と外部協力者によるアクセスが残っており、数か月にわたる偵察が検知されなかった。最初の侵入方法は公表されていない。
- **本番の秘密情報の分離（同）**: GitHub から Drift の AWS 環境に到達できた。そこに保管されていた顧客連携用の OAuth トークンが取得された。Mandiant は Drift と Salesloft 本体の環境の分離を確認しており、Salesloft 本体への到達は限定的な偵察にとどまった。
- **連携トークンの利用制限（GTIG、Salesloft）**: 窃取されたトークンは、正規の Drift 基盤以外からも使えた。Salesloft は後に「正規の Drift 通信は既知の IP からのみ」と案内した。送信元が固定されていれば、窃取トークンの悪用を検知・阻止できた。
- **業務データ内の秘密情報（GTIG、Cloudflare）**: 攻撃者は、顧客の Salesforce の問い合わせ記録などから他サービスの資格情報を探した。顧客が問い合わせ本文に鍵を貼っていたことが二次被害の入口になった。
- **止められた箇所**: Salesloft と Salesforce による全トークンの失効（8月20日）で Salesforce 経由の窃取は止まった。中央管理のクライアント鍵の全交換（9月5日）で、Drift 経由の再侵入も断たれた。攻撃者は記録を消そうとしたが、Salesforce の監査ログは残っており、被害組織は調査できた（GTIG）。
- **AI の関与**: Drift は AI チャットボット製品で、FBI も「Salesforce と連携できる AI チャットボット」と説明している。ただし侵害は開発基盤と保管トークンの窃取によるもので、言語モデルの誤動作や不正指示が原因という記述は一次資料にない。
- **帰属**: GTIG は UNC6395 と命名した。FBI は UNC6040（電話による詐欺で Salesforce に入り、ShinyHunters を名乗る恐喝が続いた集団）と並べて警告したが、両者を同一とはしていない。

#### 9. 企業AI基盤への教訓（本調査の推論）

#### 3. 欠けていた統制と止められた箇所

- **CI のトークンの範囲（AWS 説明）**: Amazon Q 拡張の CodeBuild（AWS の CI サービス）設定に「範囲が過大な GitHub トークン」があった。AWS-2025-016 によれば、信頼できない貢献者の PR を自動ビルドする設定では、ビルド環境からリポジトリ用のトークンが漏れ得た。この問題は AWS Toolkit for VS Code と AWS SDK for .NET のリポジトリで悪用された。
- **リリース前の審査（AWS 説明）**: 不正なコミットは、リリースに自動で含まれた。人による差分の承認や、配布物とレビュー済みコードとの照合が働かなかった。
- **AI エージェントの権限（一次記録）**: 混入したコードは、拡張の起動時に AI CLI を全ツール確認なしで動かし、端末とクラウド資源を削除させようとするものだった。
- **止められた箇所（AWS と NVD）**: AWS は「悪性コードは配布されたが、構文誤りのため実行に成功しなかった」と説明した。NVD の記述でも、コードは起動時に実行されるが、構文誤りのため AI CLI の呼び出しに成功しない。被害を止めたのはこの偶然の誤りで、権限の設計ではない。
- **動機（報道）**: 404 Media によれば、実行者は Amazon の AI の「見せかけのセキュリティ」を暴くためと主張した。

### 教訓（本調査の推論）

1. **AI エージェントは攻撃者にとって「端末内の高権限な実行者」である。** 確認省略・全許可モードを組織として禁止し、エージェントの資格情報から破壊系操作を外す。Amazon Q の事案で被害が出なかったのは偶然の構文誤りであり、設計によるものではない。
2. **AI と MCP の設定ファイルは秘密情報の保管場所として扱う。** 2026年の情報窃取マルウェアは、AI エージェントの MCP 設定を名指しで収集対象にした（JFrog）。平文の鍵を置かない。
3. **連携 SaaS と MCP サーバは委託先として審査する。** トークンの保管、スコープ、送信元 IP の固定、失効手順、発行者の確認、版の固定と差分審査を求める。
4. **配布物の来歴を受け入れ側で確認する。** Nx と Bitwarden では、来歴証明の欠落が異常の手掛かりだった。来歴証明がない版や公開直後の版を自動で取り込まない。
5. **被害の段階を分けて記録・報告する。** 配布、実行、収集、送出、受信を区別する。node-ipc の報告書の評価方法は、AI エージェントの事故調査にも転用できる。
6. **盗まれた鍵の二次利用を想定した設計にする。** Nx の第2段（非公開リポジトリの公開）と Salesloft（問い合わせ本文の鍵）は、最初の流出より次の連鎖の方が大きな被害になり得ることを示した。
