<h2 id="quick-facts"><strong>Quick Facts</strong></h2>

<p>GitTables is a large-scale corpus of relational tables extracted from CSV files in GitHub, that facilitates learning table representation models and applications in e.g. data management, data analysis, etc. We keep expanding GitTables to at least 10M tables (ETA: early 2023).</p>

<h2 id="about-gittables"><strong>About GitTables</strong></h2>

<p>GitTables is a large-scale corpus of 1M relational tables extracted from CSV files in GitHub. We aim at growing GitTables to at least 10M tables. Each table is distributed in its original form (e.g. with the original header), and comes with metadata like semantic type annotations of table columns. For these annotations, we used &gt;2K different semantic types from <a href="https://schema.org/" target="_blank">Schema.org</a> and <a href="https://www.dbpedia.org/resources/ontology/" target="_blank">DBpedia</a>.</p>

<p>Figure 1 illustrates our approach to creating GitTables, on a high level.</p>

<h3 id="why-gittables">Why GitTables</h3>

<p>Existing large-scale table corpora (like <a href="http://webdatacommons.org/webtables/" target="_blank">WebTables</a>) contain tables extracted from HTML pages, limiting the capability to represent offline tables. These table corpora also lack semantic annotations, like semantic column types.</p>

<p>To train and evaluate table representation models for applications beyond the Web, e.g. data management, additional resources are needed with tables that resemble relational database tables. We built GitTables to facilitate that need.</p>

<p>Example use-cases that GitTables can facilitate that may use table representation models:</p>

<ul>
  <li>Data search, integration, and validation.</li>
  <li>Data visualization and analysis recommendation.</li>
  <li>Schema completion for e.g. database or knowledge base design.</li>
</ul>

<h3 id="the-dataset">The dataset</h3>

<p>On average the tables have 25 columns and 209 rows, more detailed statistics can be found in the table on top of this page. Each table is stored in a parquet file and comes with metadata, in the form of the original URL, license, and table dimensions. Figure 2 shows an example table.</p>

<p align="center">
    <img src="images/organism_table.png" />
    <figcaption style="text-align:center">Figure 2: example of a table retrieved based on the ``organism'' query.</figcaption>
</p>

<p>We also annotated table columns with real-world concepts, semantic types, that the columns refer to. These labels were extracted from the DBpedia and Schema.org ontologies.</p>

<p>We used two different annotation methods:</p>
<ul>
  <li>Syntactic: string-based matching between column names and the semantic types,</li>
  <li>Semantic: embedding semantic types and column names using a pretrained FastText model trained on the Common Crawl dataset. The annotation corresponds to the most similar semantic type.</li>
</ul>

<p>Figure 3 presents the distribution of semantic types of the tables per annotation method and ontology.</p>

<p align="center">
    <img src="images/column_types_distributions_total.png" />
    <figcaption style="text-align:center">Figure 3: distribution of top 25 semantic types resulting from different annotation methods and ontologies.</figcaption>
</p>

<h2 id="downloads"><strong>Downloads</strong></h2>

<p>GitTables is hosted on Zenodo which ensures long-term persistence. To facilitate extension and replication of GitTables we publish the code for extraction, curation, and annotation, as well as the ontologies used for annotation.</p>

<h3 id="dataset-downloads">Dataset downloads</h3>

<p>The <a href="https://docs.github.com/en/search-github/searching-on-github/searching-code" target="_blank">GitHub Search API</a> requires queries to include a keyword, which we refer to as a topic (e.g. <code class="language-plaintext highlighter-rouge">id</code>, <code class="language-plaintext highlighter-rouge">object</code>, etc.). We kept this structure in place so each zip file download contains the tables retrieved for a topic.</p>

<ul>
  <li><a href="https://zenodo.org/record/6517052" target="_blank"><strong>GitTables 1M (16.3 GB)</strong></a>: the primary corpus of 1M tables used for the analysis in the associated paper.</li>
  <li><a href="https://zenodo.org/record/6515973" target="_blank">GitTables 1M - CSV files (6.8 GB)</a>: the CSV files of which the tables were extracted.</li>
  <li><a href="https://zenodo.org/record/5706316" target="_blank">GitTables benchmark - column type detection (3.6 MB)</a>: a smaller subset of 1101 tables and associated labels used for benchmarking semantic column type detection.</li>
  <li>GitTables (TBC): the entire dataset of 10M tables with metadata.</li>
</ul>

<h3 id="ontology-downloads">Ontology downloads</h3>
<p>The tables have been annotated with snapshots of DBpedia and Schema.org. These ontologies are provided in the form of a pickle file. Each pickle contains a pickled Pandas DataFrame with the semantic types per ontology.</p>

<ul>
  <li><a href="/assets/dbpedia_20210528.pkl" target="_blank">DBpedia ontology (509 KB)</a>.</li>
  <li><a href="/assets/schema_20210528.pkl" target="_blank">Schema.org ontology (619 KB)</a>.</li>
</ul>
