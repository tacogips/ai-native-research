# インシデント深掘りの索引と横断整理

[専門用語の日本語説明](../glossary_ja.md)。製品名・組織名・識別子は原表記を保持する。

このディレクトリは、リポジトリ内の既存資料で概要だけを扱っていたインシデントを、一次資料で深掘りした結果を置く。対象は約60件で、個人情報流出、ランサムウェア、AI関連の事故・脆弱性を含む。既存資料の概要は初報や1本の資料に依拠したものが多く、深掘りで人数・日付・原因・復元の有無に誤りが見つかった。訂正候補は80件で、72件を既存資料へ適用し、2件を保留（既存記述の誤りではない補足）、6件を除外した。反映結果は[訂正の適用記録](corrections_applied_20261008.md)にある。

## 1. 調べ方

- **分担:** 10グループに分け、Claude Opus のサブエージェントが一次資料（被害組織の発表、適時開示・決算、規制当局の処分、裁判記録、議会証言、独立調査、脆弱性報告者の原報告、CVE）を優先して調べた。Claude 側のウェブ検索がセッション上限（200回）に達した後は、既知URLの直接取得に切り替えた。AI評価中の侵入事例と角川ドワンゴ学園の漏洩は、Codex（gpt-6.1-sol）が担当した。
- **検索補完:** 全11ファイルの「未確認」項目を、Codex（gpt-6.1-sol）がウェブ検索で再調査した。結果は各ファイル末尾の「検索補完の記録」節にある。解消は約40項目で、多くは企業や当局が公表していない事項（確定損失、内部調査の詳細、訴訟の帰結）のため未解消のまま残った。
- **防御側の記述水準:** 侵入経路は「どの統制が欠けていたか、どこで止められたか」の水準で書き、攻撃手順・コマンド・回避手法・未修正の脆弱性の詳細は書いていない。一次資料が詳しく書いていても要約していない。流出データそのもの、攻撃者のリークサイトは閲覧・収集していない。
- **原本の扱い:** 取得した一次資料はGit管理外の `research/disclosures/raw/incidents/` に保存し、各ファイルの出典節にURL・取得日・SHA-256を記録した。

## 3. 横断して分かったこと

### 3.1 原因

1. **入口の大半は「認証情報」と「外部とつなぐ経路」である。** 盗まれた従業員アカウント（KADOKAWA）、多要素認証のない遠隔接続（Change Healthcare、British Library、Ticketmaster）、更新されていないVPN機器と弱い管理者パスワード（イセトー、アサヒ、半田病院）、多要素認証の例外だった委託先の管理者アカウント（アスクル）、人をだましたアカウント再設定（M&S、Co-op、Qantas）、失効していない署名鍵（Coupang）、長寿命の委任用トークン（Salesloft Drift）。高度な未知の脆弱性が入口だったのはMOVEitなど少数である。
2. **被害の大きさを決めたのは侵入後の権限設計である。** 共有データセンターや仮想化基盤の管理権限の奪取（KADOKAWA、アスクル）、管理者権限の階層分離の欠如（Capita）、区切りのないネットワーク（British Library、M&S）、共通の管理者パスワード（半田病院、大阪）、担当外まで検索できる閲覧権限（France Travail）が、少数の乗っ取りを全面停止や大量流出へ変えた。
3. **委託・再委託の連鎖が、説明と監督を難しくした。** 角川ドワンゴ学園は委託先ドワンゴの被害を当初「影響はない」と誤って説明した。イセトーは41の委託元へ波及した。尼崎市は無承認の再委託が対象1,029件中322件あった。個人情報保護委員会が指摘した中心は「委託先の監督」と「取扱状況の把握」である。
4. **検知と証拠保全が弱い。** NTT西日本グループの持ち出しは約10年、トヨタの公開設定は約9年5か月続いた。イセトーはVPN機器のログを取得しておらず、半田病院・大阪では初動の機器更新でログが消えた。警告が出ても止められなかった例（Capita、British Library、France Travail）も多い。
5. **バックアップは「ある」だけでは守れない。** アスクルは同じデータセンター内のバックアップも暗号化・削除された。逆に大阪は遠隔地の磁気テープから10日で参照用の電子カルテを立ち上げ、Railway（PocketOS）は拠点外の災害用バックアップから全データを戻した。

### 3.2 数字の扱い

- **件数は公表後に変わる。** KADOKAWA（254,241→261,956人）、Change Healthcare（500人→約1億9,270万人）、アサヒ（約229万件へ拡大）、トヨタ（215万→約230万人）。初報の数字を最終値として引用しない。
- **費用は数年続き、項目の性格が変わる。** UHGの2025年の7.99億ドルは攻撃費用ではなく貸付の引当金だった。Medibankの非経常費用は4年度で計1億6,080万豪ドル。確定損失を公表しない組織も多い。
- **研究者の評価と公式の評価を区別する。** ForcedLeakのCVSS 9.4は研究者の自己評価、Auto Modeの60〜80%は小標本、Salesloft Driftの700超は推計である。

### 3.3 AIの関与

| 関与の形 | 事例 | 一次資料で確認できた範囲 |
|---|---|---|
| 攻撃者がAIを道具として使った | GTG-1002、メキシコ政府機関、Nx s1ngularity、Bitwarden CLI、Amazon Q（実行失敗） | 自動化率などの数値は調査主体ごとの推計で、相互比較や一般化はできない |
| AI連携製品・AI基盤が侵害の入口になった | Salesloft Drift、postmark-mcp、OpenClaw、ClawHavoc、Moltbook、Hermes Agent | いずれも言語モデルへの不正指示が主因ではなく、トークン管理・配布物の改変・認可の欠落が原因 |
| 業務AIへの指示混入による流出経路 | EchoLeak、SearchLeak、Reprompt、RovoBlast、ForcedLeak、GitHub MCP、GitLost | 7件すべて研究者の実証で、実際の悪用は確認されていない |
| AIエージェントの誤動作 | Replit/SaaStr、PocketOS | 本番と開発の未分離と広すぎる資格情報が重なった。どちらもデータは最終的に復元された |
| 評価中のAIの無許可行動 | Anthropic、OpenAI/Hugging Face、英国AISI | 評価環境の外部接続・隔離・監視の不備。モデル自身の説明は原因の証拠にならなかった |
| AIの関与なし | 個人情報流出・ランサムウェアの約35件 | 一次資料でAIが攻撃や被害に関与したという記載はない |

### 3.4 企業AI基盤への示唆（本調査の推論）

- **作業主体のAIに渡す認証情報は、人の従業員アカウントと同じ失敗をする。** 長寿命・広範囲・多要素認証の例外・失効漏れが被害を決めた。専用ID、短命トークン、宛先ごとの注入、定期的な失効を基盤側で強制する。
- **AIを外部と接続する経路は、保守用VPNや委託先の常時接続と同じ攻撃面になる。** 接続の承認権限、常時接続の禁止、接続元の制限、記録の保全を、AIのツール接続・MCP・外部AIサービスにも適用する。
- **委託先としてデータを処理する場合は、処理の連鎖を利用者へ説明できる台帳を持つ。** 角川ドワンゴ学園の誤説明は、AI処理を子会社や外部へ委託する企業に直接の教訓になる。未成年者のデータは特に保存期限と最小化を設計する。
- **自然言語の禁止指示は破壊的操作を止めない。** 本番と開発の分離、破壊的操作の決定的なゲート、拠点外の復元可能なバックアップが、ReplitとPocketOSの損失を最終的に防いだ。
- **AI自身の説明を事故の原因記録にしない。** 評価中のAIの「模擬環境だと思った」という説明は後に撤回された。認可・通信・操作の記録を、AIが改変できない場所に残す。
- **件数と費用は確定するまで追い続ける。** 監査記録と事故対応の記録に、更新の履歴と根拠を残す。

## 4. 残る限界

- 約300項目が「未確認」のまま残る。多くは企業・当局が公表していない事項であり、検索で見つからないことは不存在を意味しない。
- 裁判記録の悉皆調査は行っていない。逮捕・起訴・和解の有無は、公表されたものに限る。
- 一次資料の多くは被害組織自身の発表であり、独立検証済みという意味ではない。
- 2026年10月8日時点の情報であり、係属中の訴訟・当局調査は今後変わる。
